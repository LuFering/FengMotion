## 1. 一句话定位

## 4. 修改能力的真实边界

### 4.1 可改字段（白名单，`ModifyPlanValidator.ALLOWED_FIELDS`）

`text`、`subtitle`、`color`、`backgroundColor`、`durationSeconds`

### 4.2 不支持（明确报错，不静默忽略）

图片替换、动画、转场、场景增删、选区（`scope=selection` → `unsupported_field`）。

**任一编辑项落在白名单外，整份方案拒绝**（错误码 `unsupported_field`），不做部分执行。
取消需求时输出空 `edits` 也视为失败（`modify_plan_invalid`），不会被当作「已完成」。

### 4.3 记录但不生效的约束

`preserveCamera`、`preserveCaptions`、`reuseExistingComponents` 只写入 `warning` 事件，
**不参与校验**。界面上对应开关已置灰，任务详情写「本次未提交保留约束」。

## 5. 尚未启动的关键缺口

1. **从零创作**：真实渲染入口仍主要从项目名/简报构造最小影片，
   没有「一句话主题 → 画面构想 → 分镜 → 素材 → 动画 → 成片」的完整链路。
2. **版本历史与回退**：有当前版本号、任务关联、旧视频文件，
   **没有保存每个历史版本的场景快照**。回退需要「历史快照 + 变更记录 + 恢复接口」，
   不只是加一个界面；且要恢复场景数据与素材引用，不能只换 MP4。
3. **运行恢复**：服务重启后执行中的任务停在 `running`，无恢复或中断收尾。
4. **干净环境安装验证**：当前依赖系统 Node、Chrome、`dsh`，并带本机模型配置路径，
   第三方机器可安装性未验证。
5. **启动耗时**：AppImage 下后端启动实测约 30–100 秒，启动反馈与耗时需优化。
