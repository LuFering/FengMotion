## 当前创作主路径

用户原始要求 → 项目与 Prompt-first 工作流 → `prompt.original.md` → 资源 ID 解析为文件/参考片段/技法说明 → agent 修改 Remotion 工程 → 工程快照 → 后端从快照渲染 → 提交版本与视频 → 工作台预览、继续修改或恢复工程。

不强制分镜、场景 JSON 或 Gate 审批。Structured 仍只做状态评估，普通节点产生的界面快照不等于真实工作文件。

## 接口和文件

- `GET /api/projects/{id}/workflow`：创作上下文状态。
- `POST .../workflow/init`：逐字保存原始需求；已有原文时新需求记为纠正。
- `POST .../workflow/corrections`：追加用户修改要求。
- `GET .../workflow/film`：工程是否可渲染。
- `GET .../workflow/creation`：最近一次创作状态；进程重启遗留 running 显示 interrupted。
- `POST .../workflow/create`：创作并渲染。`references` 省略时沿用最近选择；显式 `[]` 清空；失败不降级演示。
- `POST .../workflow/render`：从当前工程建立快照并渲染，提交版本。
- `GET .../scene/versions` 与 `POST .../scene/versions/{version}/restore`：版本历史与恢复。

项目内：用户原文与纠正、`resources-in-use.md`、`creation-state.json`、源码与素材、`renders/`；新工程快照在 `.fengmotion/source-snapshots/`，恢复前备份在 `.fengmotion/restore-backups/`。两者暂不自动清理。
