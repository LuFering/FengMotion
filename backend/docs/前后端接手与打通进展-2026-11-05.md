## 已查验与已修改

### 三库到消息、首次创作与后续修改

之前对话页生成 references，但 useSessions 只发送 attachments；引用在请求服务层丢失。现在发送与历史回读保留 references，回复流会解析三类资源并把用途和可读路径交给 agent。

工作台注册待发送投递通道，资源库选出的素材、参考片和技法可挂入当前输入。对话启动创作时携带已发消息中的三库引用与当前选择；工作流运行在 create 节点发送引用，后续源码修改也使用同一转换与过滤规则。

参考片区间必须为整数毫秒且位于所选片段范围，videoId 必须与片段相符。资源选择器读取素材与技法后续页；加载和失败状态独立呈现，切换视频后不允许选中上一条视频的片段。

### 初次创作、追问和恢复

之前新项目即使 agent 正常追问，也会因入口不存在而报 create_incomplete；工作流还会把追问标为失败。现在先检查工程是否变化，无变化返回 awaiting_info，工作流节点与记录显示等待补充，不推进视频版本。

creation-state.json 保存最近一轮意图、回复、引用、状态、产物、版本和错误。GET /api/projects/{id}/workflow/creation 提供回读。刷新后恢复等待问题和资源，发现运行中则轮询；后端重启遗留 running 会显示 interrupted。回答问题时将上一轮要求和问题一起提供，原始需求和后续纠正仍按项目文件读取。

references 省略表示沿用最近资源，显式 [] 表示清空。前端不会把 [] 丢掉。状态写入失败不掩盖原始执行错误，也不把已经提交的视频版本改报成渲染失败。

### 画面定位、保留条件和真实产物

源码创作路径把实际目标引用、预览版本、时间/区域和保留要求与本轮意见一起交给 agent，不再静默忽略。它们属于自然语言执行要求，没有自动验证 agent 是否遵守。

工作台空态“开始制作”进入真实创作路径；移除了只生成标题卡的占位预览旁路。工作流真实 render 产物包含可播放 URL，可进入画面列表。新结果与恢复结果刷新当前版本和预览，防止继续停留在手动选中的旧画面。

输入法确认回车不提交；长请求成功后也不会清空用户期间另写的草稿。工作台和编辑器入口区分真实创作与演示。后端没有创作取消接口，前端不再把关闭页面或取消演示记成已经取消真实创作。

### 工程快照与恢复

之前版本只存源码清单，恢复接口仅支持旧 scenes JSON，无法恢复 Remotion 工程。

现在新渲染保存 src/、public/、film.config.json、package.json 的实际副本和内容指纹，后端从该副本渲染，版本记录 sourceSnapshot/sourceHash。素材文件替换也参与变化判断，读取失败会明确报错。

恢复源码版本时校验快照及版本记录指纹，先准备文件再替换当前工程；数据库冲突或正常文件操作异常会尝试回滚。恢复前文件保留在 .fengmotion/restore-backups/，成功恢复提交为新版本并沿用历史视频。无源码快照的旧工程版本只可预览，界面不提供恢复按钮。

同一后端进程内，创作、工程渲染与版本恢复共享项目锁，返回 409 project_busy。渲染的数据库版本基线移到渲染开始前，避免渲染完才读取基线而覆盖期间的新版本。

## 接口说明

新增 GET /api/projects/{projectId}/workflow/creation，尚无记录时为空；客户端按无记录处理。

状态字段：running / rendered / awaiting_info / failed / interrupted；附带 intent、reply、references、artifactPath、version、error、updatedAt。

POST /workflow/create 保留原响应结构：rendered 有产物与版本，awaiting_info 无产物/无版本。未修改工程是等待的保守判据，并不证明模型一定在提问。

POST /scene/versions/{version}/restore 新支持带 sourceSnapshot/sourceHash 的 project-render 快照；旧源码版本返回 422 source_snapshot_unavailable，坏快照返回 snapshot_corrupt。源码项目不能恢复成只有旧 scenes 数据的历史版本。

## 仍需处理的边界

1. 自动参考片分析仍不可用，检索仍主要是文本/结构化字段；本次没有新增视频理解模型。
2. 对话内直接上传的 fileId 附件仍走图片消息通道，与三库 assetId 不是同一身份；尚未自动转为制作素材。三库资源已经走独立引用通道。
3. 多轮对话启动项目按顺序连接用户原话作为初始需求，不采用 AI 回复中的未确认推断。直接上传的图片附件仍需先转入素材库，模型对图片的口头解释不会自动成为可复用的素材或分析记录。
4. 工作流图、演示快照和历史仍部分保存在浏览器，尚未迁移成统一持久执行器。Structured 不会自动生成产物。
5. 创作仍为长 HTTP 请求，暂无可靠取消、完整实时工具进度和渲染失败后的自动修复重试。
6. 项目锁仅保护同进程相关服务，不是跨进程锁，也不能阻止对话 agent 或外部程序写同一项目。
7. 快照只覆盖列出的工程文件，不冻结系统依赖、网络文件和工程外的绝对路径。恢复与 SQLite 提交不是跨资源原子事务，进程强杀期间需检查备份；快照与备份暂不自动清理。
8. 独立场景编辑器和源码工程尚无双向转换；视觉审片、技术质量检查与交付判断仍需完善。
9. 本次构建不等于已安装应用已更新。系统 Node、DSH/模型配置、Linux 系统能力依赖及干净机器安装仍需处理和验证。
