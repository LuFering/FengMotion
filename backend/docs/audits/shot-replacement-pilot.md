# 可替换镜头 · 后端验证样例

本样例复用 FengMotion 的项目渲染器，在临时目录运行，不需要启动桌面、前端或 Java 服务，不读改业务数据库。画面参考 `coffee` 的柱状图与片尾独立制作，没有使用或修改原项目文件。

## 验证路径

1. 宿主固定 30 fps、960×540；装配清单固定 `chart`（0–4 秒）、锁定 `outro`（4–7 秒）及独立、可听的英文合成旁白。组件提供绘制和共享主题样式，宿主负责画布与时序。
2. 用柱状图渲染基线。生成 `shot-context.json`，包含目标槽位、主题数据、旁白文本及时间区间、相邻镜头的参考产物。测试的排名卡片是仓库内预先写好的源码，并非现场调用 DSH；该上下文文件示范后续创作作业应提供哪些只读信息。
3. `replace-shot-source` 绑定基线版本和目标 ID，仅允许更换这个槽位登记的组件。越权目标、音频/时长字段及过期基线都会被拒绝。故意破坏的组件必须在真实编译时失败，失败后当前版本仍为 v1。
4. 仅渲染 120 帧排名卡片，混入对应旁白生成 `preview.mp4`，确认前不推进版本。试验脚本自动进入提交阶段，不涉及真实用户确认。
5. 从时间线拼接新镜头和已渲染片尾，原始旁白直接复用。校验 210 帧的显示时间、非目标 90 帧的解码像素哈希、原 AAC 音频包的哈希和时间戳，再将当前版本指向 v2。重复提交旧基线被拒绝。

Remotion 即使没有声明音频，也可能输出比画面更长的静音 AAC 流。本样例先提取每个镜头的纯画面流，再按时间线拼接。直接拼原始 MP4 曾让片尾首帧从 4.000 秒偏移到 4.053 秒；仅比较帧数或像素哈希会漏掉这个错误。

2026-11-20 本机复测：局部预览 120 帧，成片 210 帧且时序连续；片尾 90 帧及旁白 330 个 AAC 音频包一致。目标镜头编译和渲染共 7.46 秒；已有镜头和音频就绪后，最终流复制拼接耗时 42 毫秒。以上为单次本机测量。

## 复跑

在仓库根运行，需现有 Remotion 依赖、Node、`ffmpeg`、`ffprobe`、`espeak-ng` 和已安装的 headless Chromium。不会启动交互浏览器；不指定 headless Chromium 路径时不运行。

```bash
node --test backend/src/test/shot-replacement.test.mjs
FENGMOTION_CHROME=/absolute/path/to/chrome-headless-shell \
  node backend/src/test/shot-replacement/run.mjs
```

命令打印临时目录；其中 `v1.mp4` 是基线、`preview.mp4` 是带配音的局部预览、`v2.mp4` 是通过校验的成片、`result.json` 是实测报告（包含镜头编译与渲染总耗时、拼接耗时及校验结果）。退出时保留这些文件供检查。

## 尚未验证的边界

- 只覆盖两个不重叠的硬切镜头、同规格视频和独立音轨，不假设转场或跨镜头视觉效果可以这样缓存与拼接。
- 只运行仓库内受信样例；目录分离不是执行沙箱，尚未允许任意 Agent 代码进入此运行流程。正式接入还需要限制代码进程可见的文件、依赖与网络，以及锁定共享资源。
- `current.json` 的替换只是单进程验证，不是跨请求的并发提交实现。生产接入应复用创作作业和数据库的版本条件提交，并绑定预览与确认所用的候选内容。
- 此脚本未接工作台或生产草稿流程，也不迁移旧工程。后续在现有异步作业提供了独立的[首次创作镜头装配试点](../shot-timeline.md)，仍未接生产镜头替换。
