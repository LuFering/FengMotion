# 契约 · 我的素材界面与现有后端

2026-11-21。本轮 UI 实施契约，配合 `asset.md`；本文描述已核对的当前实现及前端规则，不宣称旧文档全部冻结。后端端点前缀为 `/api`。本轮不要求新增后端能力。

## 数据与显示

| 数据 | UI 使用 | 约束 |
|---|---|---|
| `id/name/mediaType/mimeType/sizeBytes` | 唯一卡片、文件名、类型和大小 | 以 id 合并，不能用文件名去重 |
| `width/height/durationMs` | 预览规格 | 缺失显示空缺，不填 0；适配层将毫秒转秒 |
| `folderId/tags/sourceType` | 组织与筛选 | `★` 是现行收藏标记，用户标签展示时排除 |
| `refs` | 引用数量、引用项目、删除保护提示 | 列表带 `include=refs`；待发送不能当 refs |
| `processingStatus/availability` | 处理异常、停用/弃用、加入按钮 | 未 ready 或非 enabled 禁止新增待发送；授权未知不冒充已获授权，也不自动等于停用 |
| `reviewStatus/licenseStatus/licenseDetails` | 独立审核和授权字段 | 合法审核流转沿用 asset.md；审核不改变授权 |
| `demo` | 显式演示标记 | 与来源正交 |
| `createdAt/lastUsedAt` | 导入/使用排序 | 浏览不写使用时间；未记录使用时间不伪装为使用过 |

## 读取、筛选与预览

- `GET /assets?limit=200&cursor=…&include=refs` 循环取全页；`GET /asset-folders` 加载文件夹。失败展示重试，不能替换为“空库”。当前分页有 100 页防循环上限，达到上限且仍有游标时报错，不静默展示不完整计数。
- 当前界面在已加载集合上筛选：组织范围 → 搜索（名称、标签、授权说明）→ 类型 → 排序。类型标签计数基于前两步，左侧组织计数基于全库，结果数量基于全部条件。去掉旧的隐式来源文本搜索，以搜索文案为准。
- 排序 `recent` 是前端“最近导入”（createdAt 倒序），`used` 为 lastUsedAt 倒序且未使用置后；名称中文自然排序，大文件/长时长优先。不要把这两个前端排序名直接当旧 API sort 语义。
- `GET /assets/{id}` 返回完整资源；当前本地文件访问通过 `/assets/{id}/content` 与 `/thumbnail`，支持 Range。现有实现是本地内容端点，尚非 asset.md §4 描述的短期签名 URL；UI 不存 URL 到持久化清单。媒体加载失败提供重试。

## 导入

- 普通导入：`POST /assets/uploads` → `PUT /assets/uploads/{uploadId}/chunks/{index}` → `POST /assets/uploads/{uploadId}/complete` → `GET /assets/{assetId}`。当前客户端已支持 `UploadOptions.folderId`，从开始导入时的文件夹快照传入。
- 当前完成响应是上传完成结果（客户端读取 assetId），不是旧文档承诺的直接 Asset；继续使用现有解析器。
- 页面显示“正在导入 i/n · 文件名”，n/i 来自本次文件列表和实际回调；不编造已上传百分比。批次运行中禁止重复发起，旧卡片可继续浏览。
- 返回同一 id 时覆盖该条快照，不追加重复卡片；不改已有素材的原文件夹。失败保留 File 和实际错误，仅在当前页面内可重试失败项；关闭结果释放失败文件。
- 每批成功返回都从服务器 Asset 刷新视图。失败不能显示为已导入；去重后只显示一次。

## 更新与文件夹

- `PATCH /assets/{id}` 前 GET 当前 etag，带 `If-Match`。服务端快照确认后更新前端；失败保留原值并显示原因。当前冲突为 `409 etag_mismatch`，旧文档的 `412` 不能当唯一失败码。
- `POST /assets/batch-update`：`{ids, folderId?, addTags?, removeTags?}`；folderId 缺省不改，空串移回根目录。结果 `{results:[{id,ok,asset?,error?}]}`；200/207 都逐项解析，缺少确认结果视为失败，禁止推断成功。
- 文件夹 `POST/PATCH/DELETE /asset-folders[/{id}]`；重复名称冲突按真实错误显示，删除文件夹将素材移回根，不删除素材。请求期间禁用重复提交，失败保留输入/确认上下文。
- `POST /assets/batch-delete` 逐项处理；被引用项由后端拒绝，保留卡片和选择。全部失败不能提示成功。

## 待发送与参考片

- 待发送使用已有 `fm-pending-assets-v1`，只存 id、用途与备注等；最多 24 项、按 id 去重。UI 分辨已存在、数量上限、不可用三类反馈，不把达到上限写成“已在待发送”。部分新增后保留尚未加入的选择供处理。
- 加入不发起制作、不改变 refs，也不修改 lastUsedAt。后续实际发送逻辑遵循既有对话契约。
- `registerVideoFromAsset` 复用素材登记参考片，按钮叫“加入参考片库”；已登记显示“已在参考片库”，不叫“转入”（原素材仍在），不称已经解析。保留现有真实客户端与去重响应。

## UI 状态与键盘

- 空库、筛选无结果、加载失败是三个不同状态。首次读取失败计数为“数量未知／—”，保留旧集合时标“未更新”。
- 1200px 以下详情使用原生 modal dialog，背景不可交互，焦点循环并在关闭后恢复卡片；桌面用布局内 aside。
- Escape 先退出输入/弹层，再关闭详情，再退出多选；不能取消改名时同时关闭整页详情。
- 浏览卡片与勾选分开；方向键移动焦点，Enter 查看，Space 在选择模式下勾选。子按钮/输入框不触发卡片快捷操作。
- 所有写入与破坏性动作只在用户触发后执行；预览测试不写用户真实素材。测试写操作使用浏览器内存夹具或专用临时素材。

## 2026-11-23 补充 · 显示规则（配合[重做方案](../design/我的素材重做方案-2026-11-23.md)）

本节只改前端怎么展示已有字段。**不新增后端接口或字段**，上面各节的读写语义不变。

### 后端字段 → 界面位置（各字段只放在一个主要位置）

| 字段 | 卡片 | 列表 | 详情 |
|---|---|---|---|
| `name` | 第一行，单行省略 | 名称列 | 标题，可原地改名 |
| `mediaType` + `name` 扩展名 / `mimeType` | 底部规格行开头的格式（`PNG`） | 名称列内的铭牌 | 标题下规格行；「格式」只写铭牌，MIME 放悬停提示 |
| `width/height` | 第二行 | 时长/尺寸列 | 规格行与信息 |
| `durationMs` | 底部规格行，格式之后（视频、音频） | 时长/尺寸列 | 规格行与信息 |
| `sizeBytes` | 第二行末尾 | 大小列 | 规格行与信息 |
| `refs` | 第二行右侧「引用 n」，0 不显示 | 引用列，0 显示 `—` | 使用位置 |
| `sourceType` | 不显示 | 来源列 | 信息 |
| `licenseStatus/reviewStatus` | 只在异常时出现状态签 | 授权列、审核列 | 授权与审核 |
| `processingStatus/availability` | 只在异常时出现状态签 | 名称后附注 | 预览区提示，禁用加入按钮 |
| `createdAt/lastUsedAt` | 不显示 | 不显示 | 添加时间、最近使用 |
| `demo` | 「演示」角标（`.mya-demo`） | 名称后附注 | 标题下规格行 |

缺失值（`width/height/durationMs` 为 null）一律不显示该项，不写 0；详情信息行写 `—`。

### 卡片状态签

每张卡最多一枚，按下面顺序取第一个命中的。没有命中就不出现：

| 优先级 | 条件 | 文字 | 色调 |
|---|---|---|---|
| 1 | `processingStatus=failed` | `processingError` 或「处理失败」 | 危险 |
| 2 | `availability=deprecated` / `disabled` | 已弃用 / 已停用 | 危险 / 中性 |
| 3 | `processingStatus=pending` / `processing` | 等待处理 / 处理中 | 中性 |
| 4 | `licenseStatus=restricted` | 限制使用 | 危险 |
| 5 | `reviewStatus=rejected` | 未通过 | 危险 |
| 6 | `reviewStatus=needs_review` | 需复核 | 警示 |
| 7 | `licenseStatus=attribution_required` | 需署名 | 警示 |

- `licenseStatus=unknown`、`reviewStatus=none / pending / approved`、`licenseStatus=allowed` 是常态，卡片上**不提示**。它们仍在列表列、详情和左侧「授权与审核」分类里可见，不隐藏。
- 状态签是「圆点 + 文字」，不能只用颜色或只用图标。
- 列表和详情里，常态值用最浅灰的纯文字；需要处理的值才带彩色圆点。

### 日期

统一用本地时区：当天「今天 14:20」；同年「11月5日 14:20」；跨年「2025年11月5日」。与工作流列表一致。

### 类型筛选

- 计数口径不变（组织范围 + 搜索之后）。
- 只列出计数大于 0 的类型和当前选中的类型；「全部」不带数字，结果数只在范围标题旁出现一次。
- 读取中或数量未知时，类型按钮的数字显示 `—`，五个类型全部列出。

### 详情操作

- 一行：「加入待发送」（`.mya-use-primary`，唯一实心按钮）+ 收藏 + 更多。
- 更多菜单：重命名、复制文件地址、加入参考片库（已登记时为「已在参考片库」并禁用，仅视频）、删除（单独分隔，二次确认）。
- Escape 顺序在原有规则前加一层：先关更多菜单 / 删除确认，再退出输入，再关详情，再退出多选。

### 回归测试依赖（`tests/assets-ui.mjs`）

以下类名保持不变：`.mya-card` `.mya-row` `.mya-thumb` `.mya-types` `.mya-result-count` `.mya-demo` `.mya-use-primary` `.mya-inspector` `.mya-import-status` `.mya-pickbar` `.mya-dock-pop` `.mya-org-foot`。文案「批量选择」改为「选择」、「重置筛选」改为「清除筛选」，测试同步修改。

### 本轮不做（需要后端时另开契约）

- 透明通道检测：当前前端按格式推断，PNG / WebP / GIF / SVG / AVIF 铺棋盘底，JPG 等不铺；不检测像素。
- 服务端搜索、分页滚动与虚拟列表：当前仍一次读完全库再在前端筛选。

## 2026-11-23 补充 · 按项目整理（配合 asset.md「归属项目」）

- **数据**：`Asset.projectId`（null = 未归属）。归属只有一个，用来整理；`refs` 仍表示「被谁用到」，两者互不推断。
- **项目列表**来自 `GET /projects`（App 传入 `projects`），不再从 `refs` 推导；没有素材的项目也列出，计数 0。
- **分类栏**：「全部素材 / 收藏 / 最近使用」→「项目」组（未归属 + 各项目，当前项目排最前并标「当前」）→ 文件夹 → 来源 → 授权与审核。旧的「引用项目」分组删除。
- **筛选**按项目 ID（`proj:<id>`），不按项目名称，项目改名后仍对得上。
- **从项目进入**素材页时默认停在该项目分类（`currentProjectId`）；换项目时页面按项目重建。
- **导入**：所在分类是某个项目时，上传带 `projectId`，素材归属该项目；在其他分类导入为未归属。
- **改归属**：详情「信息」里的「项目」下拉（含「未归属」）；批量操作坞「移至项目」。两者都只按服务端确认结果写回，失败如实提示。归属的项目已归档或不在列表里时，下拉显示「项目不可用」，不冒充未归属。
- **空态**：项目分类下没有素材时显示「「项目名」还没有素材」并给出导入入口，不显示成「筛选无结果」。
- **生成结果自动归属**：未实现，后端尚无写入生成结果素材的流程。
