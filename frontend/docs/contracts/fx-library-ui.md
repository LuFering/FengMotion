# 契约 · 特效库界面与现有后端

2026-11-23。本轮界面实施契约，配合 [library.md §2](library.md) 与 [打磨方案](../design/特效库打磨方案-2026-11-23.md)。**本轮不新增后端接口或字段**；末尾列出需要后端补的数据，另开契约实施。后端前缀 `/api`。

## 1. 读取

| 端点 | 界面用途 | 约束 |
|---|---|---|
| `GET /fx-techniques?limit=&cursor=` | 读取全部技法，前端做搜索、筛选、排序 | 循环取完；读取中与读取失败是两个状态，失败不显示成「没有技法」 |
| `GET /fx-techniques/facets` | 全量计数（当前界面用本地计数，口径相同） | 不受当前筛选影响 |
| `GET /fx-techniques/{id}` | 详情 | 列表项字段可能较少，详情以此为准 |
| `PATCH /fx-techniques/{id}/state` | 收藏、最近浏览 | 失败保留原状态并提示；不写进参考片偏好 |
| `GET /fx-techniques/semantic?...`（已有） | 语义检索排序 | 不可用时界面明确写「按关键词字面匹配」 |
| 静态 `fx-original-posters/manifest.json` | 原始场景封面 | 前端资源，不是后端字段；缺失时不阻塞列表 |

## 3. 显示规则

- **筛选组显隐**：源库能力、实现方式、输入素材、复杂度、预览类型这几组，只在当前全部技法里出现至少两种取值时显示；当前已选的值无论如何保留可见，方便取消。
- **分类选项**：只列出计数大于 0 的分类与当前选中的分类。
- **范围页签**：「精选」为 0 且未选中时隐藏；「收藏」「最近使用」即使为 0 也保留（它们有专门的空态引导）。
- **不得**因 `execType=runnable` 显示「可执行」；不得给缺失的说明、许可补默认文案。

## 5. 需要后端补的数据（本轮不做）

| 需求 | 现状 | 建议 |

## 6. 第二轮补充（2026-11-23 下午）

仍不新增后端接口或字段。

- **工具条**：分类、来源、排序三个下拉同款（共享 `DropdownMenu`，单选）。分类从筛选浮层移出；「筛选」按钮仅当 §3 中至少一组可显示或已有选中值时出现。
- **分组**：排序为「按分类」且分类为「全部」时按 `FX_CATEGORIES` 顺序分段，段内保持服务端顺序；每段标题 = 中文分类 + 数量；空段不出现。其它排序或已限定分类时不分组。
- **详情上一条 / 下一条**：顺序 = 当前墙的可见顺序（含搜索、筛选、排序、分组）；←/→ 键同效（焦点在输入框内时不响应）；切换时记入最近浏览，与点卡片打开一致。打开的技法不在当前可见列表中时（例如从「同类技法」跳入），不显示计数与切换。
- **详情加入待发送**：与卡片上的按钮同一函数、同一去重规则；已在待发送时按钮显示「已在待发送」并禁用。
- **链接显示**：GitHub 地址显示为 `github.com/<owner>/<repo>`，完整地址放在 `title` 与 `href`，不改写数据。

## 7. 第三轮补充（2026-11-23 下午）

仍不新增后端接口或字段。

- **用于工作流的目标**：只来自 `GET /projects`（前端 `useProjects`，由 App 传入），不得读演示常量 `PROJECTS`。为空时不显示假项目，给出引导文案。写入仍是本地意向清单 `fm-fx-usage-outbox-v1`，字段不变 `{techniqueId, techniqueName, projectId, projectName, at}`。
- **弹窗**：详情、用于工作流、导入来源都走共享 `Dialog`；遮罩轻压暗、不模糊背后页面。
- **读取中**：骨架卡与真实卡同尺寸；读取失败仍是独立状态，不显示成空库。
