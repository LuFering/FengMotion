# 参考产品拆解（design-references）

> 每个参考产品解决一个具体的交互问题。**不要机械复制某个产品的整套 UI**；
> 统一视觉语言按 `design-system.md`，只借鉴结构与交互。

## 工作流产品主参考（2026-10-16 增补，优先于基础参考）

> 结论：React Flow / Dify / ComfyUI 是**底层与调试**参考；工作流**产品界面**
> 的主参考改为下面 5 个 —— 让创作流程而非技术配置成为中心。

### R1. Runway Workflows —— 创作逻辑（最贴近产品定位）

- **借鉴**：节点如何展示媒体输入与输出；多个生成步骤如何连接；
  如何复用模板并快速创建变体；**创作流程而非技术配置成为用户的中心**。
- **用在**：工作流广场（模板组织）+ 编辑器（节点媒体化）。
- **链接**：runway.com/workflows · help.runwayml.com（Building your first Workflows）

### R2. Figma Weave —— 编辑模式 / 使用模式两种界面

- **借鉴**：把节点工作流包装成可反复使用的 **Tool**：重要输入暴露给使用者，
  不必每次进入完整画布。
- **用在**：工作流使用页 —— 工作流模板 → 直接创作 → 需要时再深入定制。
- **链接**：help.weavy.ai/en/articles/12267755-tools

### R3. InvokeAI —— Workflow Library + Linear View

- **借鉴**：除了节点编辑器，提供 Workflow Library（库）与 **Linear View**
  —— 把工作流中重要输入字段整理成简单操作界面；工作流保存、标签筛选、
  参数暴露、节点缓存。
- **用在**：使用页的核心范式（复杂节点图 → 简单表单）。
- **链接**：invoke.ai/features/workflows/editor-interface

### R4. Langflow —— 修改后快速验证

- **借鉴**：节点画布 + 组件配置 + 实时测试 + 工具调用观察 + 日志；
  「修改一个节点后如何快速验证结果」。
- **用在**：编辑器单节点测试与 Playground 体验（不必照搬其整体视觉）。
- **链接**：docs.langflow.org/concepts-playground

### R5. n8n —— 执行追踪与错误恢复

- **借鉴**：运行记录、节点失败、数据流向、重试；编辑、运行、执行历史
  同属一个工作区。
- **用在**：编辑器底部执行面板、历史运行记录、局部重跑。
- **链接**：docs.n8n.io
- **不要抄**：通用自动化平台的整体形态。

## 基础参考（6 个）

### 1. React Flow —— 画布技术底座（不是产品界面参考）

- **借鉴**：可拖拽节点、连线、节点配置、画布缩放、自动布局、执行状态的
  **技术实现**；官方 AI Workflow Editor 模板可直接复用。
- **用在**：`工作流` 编辑器的画布层（产品界面按 R1-R5 与 `workflow-spec.md` 设计）。
- **链接**：reactflow.dev/ui/templates/ai-workflow-editor · reactflow.dev/examples
- **不要抄**：默认的浅色示例皮肤 —— 视觉按 FengMotion 设计系统重新做。

### 2. Dify —— AI 流程编排与执行调试

- **借鉴**：模型调用/知识检索/工具/条件分支/人工审核的可视化编排；
  节点输入输出面板；运行追踪（每节点耗时、输入输出、失败原因、重试）。
- **用在**：工作流编辑器的「底部执行与调试」区；参考片检索、特效检索节点的配置范式。
- **链接**：dify.ai/workflows · docs.dify.ai/guides/knowledge-base/retrieval

### 3. ComfyUI —— 生成式视觉工作流与参数配置

- **借鉴**：节点画布 + 节点库 + 工作流 + 生成队列的组织方式；
  参数面板与结果预览。
- **用在**：特效执行节点、镜头生成节点、任务队列、生成结果预览。
- **链接**：support.comfy.org/articles/7675456845-the-comfyui-interface
- **不要抄**：面向技术用户的高复杂度 —— 节点卡片只表达流程，
  复杂参数放右侧检查器，保持画布清晰。

### 4. ShotDeck —— 参考片库的检索与视觉浏览

- **借鉴**：可搜索的电影画面大图网格、视觉筛选、镜头发现、参考画面浏览。
- **用在**：参考片库的搜索首页、镜头卡片、视觉标签、单镜头详情页。
- **链接**：shotdeck.com
- **不要抄**：只做海报收藏夹 —— FengMotion 必须展示镜头时间码、运镜、
  节奏、转场及分析证据。

### 5. Motion Index —— 视频片段与分镜灵感板

- **借鉴**：商业影片/动态设计的逐镜头索引；视频画布；相似镜头发现。
- **用在**：参考片详情、关键镜头时间线、镜头序列对照、
  把参考片段拖进创作任务的交互。
- **链接**：motionindex.io/features/canvas

### 6. Cosmos —— 灵感探索与知识关联

- **借鉴**：发现页、相似内容、关联收藏集 —— 从一个参考镜头继续探索
  相关风格、构图与视觉主题。
- **用在**：参考片的关联探索、特效之间的关系、相似技法推荐、知识图谱入口。
- **链接**：help.cosmos.so/en/articles/11717949-discovery

## 知识系统补充参考（3 个）

### 7. Kive —— 特效库与我的素材（一份参考、两套界面）

- **借鉴**：可搜索的视觉资产库、可复用预设、版本记录、提示词库、
  从创作到整理的连续体验。
- **用在**：
  - 特效库 → 「效果、参数、依赖、如何调用」；
  - 我的素材 → 「文件、预览、格式、尺寸、所属位置」。
- **链接**：kive.ai/features

### 8. Fabric —— 参考片库的语义检索

- **借鉴**：视频/脚本/分镜/参考素材的语义搜索；相似画面发现；
  视频参考板；跨素材检索。
- **用在**：参考片库语义搜索、跨素材检索。
- **扩展方向**：镜头级知识 —— 点一个片段即见时间码、构图、运镜、
  节奏、关联技法与分析来源。
- **链接**：fabric.so/for/video-editors

### 9. NVIDIA Cosmos Dataset Search（仅参考组织方式）

- **借鉴**：视频集合与检索结果的组织方式。
- **用在**：检索结果的呈现结构 —— 但**必须用创作者术语与视觉预览**，
  不得呈现成工程数据管理系统。
- **链接**：docs.nvidia.com/cosmos/cds/latest/ui-user-guide.html

## 三库设计定位（对应 `knowledge-library-spec.md`）

| 库 | 类型 | 用户主要动作 | 主参考 |
|---|---|---|---|
| 参考片库 | 视觉探索型 | 发现、比较、分析、引用 | ShotDeck + Motion Index + Cosmos + Fabric |
| 特效库 | 技法目录型 | 理解、测试、组合、复用 | Kive + ComfyUI 参数配置体验 |
| 我的素材 | 文件管理型 | 导入、查找、整理、选择 | Kive 资产组织 + 传统文件管理 |

三者共用：搜索框、标签组件、卡片基础样式、详情抽屉。
三者**不共用**：页面模板、数据模型。
