# 特效库打磨方案 · 2026-11-23

状态：本轮实施依据。适用 React 主前端 `frontend/src/features/fx/`。配套契约见 [特效库界面契约](../contracts/fx-library-ui.md)；数据语义以 [library.md §2](../contracts/library.md) 为准，不改。

## 1. 特效库是什么、用来做什么

- **只读的技法目录**：回答「用什么方法实现这个效果」。条目来自本地能力库导入（当前 remotion-scenes 204、video-shotcraft 124、lemo-opuscar 51，共 379 条）。界面不新增、不修改技法本身。
- **用户状态另存**：收藏、最近浏览走 `PATCH /fx-techniques/{id}/state`，和参考片偏好不混用。
- **能力标签 ≠ 本机可执行**：`execType` 是来源库自己的声明，`executionStatus` 才回答这台机器能不能跑。当前 379 条全部是 `reference / not-implemented`，所以界面上不能出现「可执行」的暗示。
- **用到哪里**：选中的技法作为知识参考进入待发送，交给创作对话；「用于工作流」只记入本地意向清单，调用链未接入。

用户主线：**按效果找 → 看画面认出是不是要的 → 看用途与做法 → 收藏 / 加入待发送 / 复制配方**。

## 2. 现状问题（2026-11-23 实测：1440×900，深色与浅色，真实 379 条）

| 位置 | 问题 | 原因 |
|---|---|---|
| 筛选浮层 | 六组条件，五组没有区分作用 | 真实数据里能力全是「知识参考」、实现全是「AI 生成」、复杂度全是 3、输入全为空、没有动态预览；「光影」0 条也列着。用户点了也筛不出东西 |
| 范围页签 | 「精选 0」常驻 | 0 条的入口只会让人点进空页 |
| 卡片 | 卡片 315px，标题 17px，1069 宽只放 3 张 | 列宽下限 300px，和素材页刚调好的紧凑密度不一致 |
| 卡片 | 204 张卡的用途说明是空的，卡底只有名称；分类标签都是「合成」 | 293 条落在「合成」一类，分类本身区分度低；来源库自带的二级分类（ThemeAnimations、RollerAnimations…）没有显示 |
| 详情 | 大多数技法打开后没有画面，只有一段文字 | 详情只读 `previewImage`（51 条有），卡片用的原始场景封面没有传进来 |
| 详情 | 技术细节里「分类」显示 `camera` 这类原始值 | 直接读了 `categoryLabel`，导入时没有翻成中文 |
| 详情 | 打开时背后整页重度模糊 | 遮罩与模糊过重，和素材页详情的观感不统一 |
| 页头 | 标题「特效技法库」与导航「特效库」不一致 | 两处命名各自写 |

## 3. 设计方向（沿用工作台与素材页的做法）

1. **画面是主角**：卡片和详情都以真实画面开头，文字压在画面底部渐变上。
2. **只给有用的控件**：筛选只显示在当前数据里能分出不同结果的条件；0 条的分类、0 条的「精选」不出现（当前选中的除外）。
3. **一处信息一个位置**：能力标签全部相同就不逐卡重复；来源和版本收进详情的技术细节。
4. **如实**：名称保留来源原名，不擅自翻译；缺说明就不显示那一行，不补默认文案；「仅参考」的提示保留在详情操作旁。
5. **层级靠字号、字重、灰阶**，不加框套框、不用发光。

## 4. 具体改动

### 4.1 页头与工具条
- 标题改为「特效库」（与导航一致）。右侧「选择」「导入来源」两个次要按钮保持。
- 范围页签：「精选」为 0 且未选中时隐藏；计数用浅灰。

### 4.2 筛选浮层
- 分类：只列出计数大于 0 的分类和当前选中的分类。
- 源库能力、实现方式、输入素材、复杂度、预览类型：一组只在当前技法里出现至少两种取值时才显示；否则整组不出现。
- 全部组都不显示时，浮层只剩分类，底部「清空筛选」照旧。

### 4.3 技法卡
- 网格最小列宽 300 → 216px（与素材页一致）：1069 宽 4 列，1440 宽 5 列。
- 卡片 16:10 画面铺满，底部多段渐变。三层文字：
  - 首行（10.5px，浅白 0.6）：分类 · 来源二级分类（来源有时才显示，例如「合成 · ThemeAnimations」）。
  - 名称：14px / 550，单行省略。
  - 用途：12px 一行省略；没有用途说明就不显示这一行。
- 卡片内侧一圈极淡高光；悬停描边提亮一档；选中、已在待发送的状态沿用。
- 画面上的「加入待发送」「收藏」按钮 26px，图标 13px。

### 4.4 详情
- 预览区用和卡片同一张画面：优先 `previewImage`，没有则用原始场景封面；两者都没有才不显示预览区。
- 「技术细节 · 分类」写中文分类；来源自带的二级分类另起一行「来源分类」，只在有值且与中文分类不同时显示。
- 遮罩改为轻遮罩（不再整页重度模糊）。

## 5. 视觉规范（作用域 `.fxlib`）

| 项 | 值 |
|---|---|
| 网格 | `minmax(216px, 1fr)`，间距 14px（与素材页同一密度） |
| 卡片 | 16:10，圆角 10，描边 `--line`，内侧高光 `rgb(255 255 255 / .06)` |
| 卡片文字 | 首行 10.5 / 名称 14·550 / 用途 12；画面上文字固定白色系，三套主题一致 |
| 画面按钮 | 26px，半透明深底 `rgb(10 11 14 / .64)`，白色图标 |
| 动效 | 只做颜色与透明度过渡 .15s |

## 6. 本轮不做（需要后端或数据导入，记入契约）

- 技法中文显示名、来源二级分类的中文名。
- 补齐用途说明、预览图与动态预览；海报目前由前端 `fx-original-posters/manifest.json` 提供，应改由后端返回 `previewImageUrl`。
- 分类重划（293 条都在「合成」）。
- 执行适配器与工作流调用链。

## 7. 验收

- 1069×681、1440×900；深色、浅色、触感三套主题截图。
- 筛选浮层在真实数据下只剩有区分的组；「光影」「精选」不出现。
- 随机打开 3 条没有 `previewImage` 的技法，详情都有画面；技术细节里没有英文原始分类值冒充中文分类。
- 构建、单元测试通过，lint 不新增。

## 8. 第二轮：使用与观感（2026-11-23 下午）

第一轮把信息理顺了，这一轮解决「用起来顺不顺、看起来细不细」。

### 8.1 实测问题

| 位置 | 问题 |
|---|---|
| 工具条 | 「来源」「排序」是系统原生下拉，弹出样式与主题无关；筛选浮层只剩 6 个分类，为它单开一层不值 |
| 墙 | 「按分类」排序时 293 张「合成」连成一片，看不出分段 |
| 详情 | 预览 404px 占弹窗一半以上，往下滚标题和操作就不见了 |
| 详情 | 主按钮「复制配方」没有底色，看不出主次；卡片能「加入待发送」，详情反而不能 |
| 详情 | 看下一条只能关掉再点另一张卡 |
| 详情 | 技术细节里复杂度、版本是等宽字体；链接整串铺开 |
| 卡片 | 键盘聚焦时没有清晰的焦点环；悬停只有边框变化，反馈偏弱 |

### 8.2 改动

1. **工具条统一为同款下拉按钮**：`分类 ▾` `来源 ▾` `排序 ▾`，用共享 `DropdownMenu`，单选带勾和计数，按钮在有选择时高亮并显示所选值（例如「分类 · 转场」）。分类从筛选浮层移到工具条；「筛选」按钮只在其它条件能分出结果时出现（真实数据下不出现）。
2. **按分类分组**：排序为「按分类」且未限定分类时，墙按分类分段，每段一个标题（分类名 + 数量），标题滚动时吸顶。其它排序不分组。
3. **详情弹窗**：
   - 预览限高 `min(340px, 40vh)`，画面完整显示（contain），深色底台。
   - 标题上方加一行「分类 · 来源」；名称下方是说明。
   - 操作行：**加入待发送**（主按钮，实底）· 复制配方 · 用于工作流，「仅参考」在最右。
   - 标题与操作行在正文滚动时吸顶（预览滚出后仍能操作）。
   - **上一条 / 下一条**：弹窗右上关闭键旁两个按钮，←/→ 键同效，顺序与当前墙一致，显示「12 / 379」。
   - 技术细节用正文字体；链接只显示 `github.com/…/仓库名`，完整地址放 title。
4. **卡片**：键盘焦点环 2px 强调色内描边；悬停时画面缓慢放大 1.03（.5s），文字层不动；已在待发送的卡片左上角显示「已加入」小签。

### 8.3 不做

- 卡片画面里自带名字（AURORA、BOKEH）与标题重复——是封面数据本身，后端补显示名后再看。
- 列表视图、批量收藏。

### 8.4 验收

- 三个下拉在深/浅/触感下样式一致，Esc 关闭、方向键可选。
- 「按分类」下能看到 6 个分段标题且吸顶；改成「名称」后分组消失。
- 详情 ←/→ 连续切换 3 条，焦点留在弹窗内，计数正确；到头/尾按钮禁用。
- 详情滚到底时名称和「加入待发送」仍可见。

## 9. 第三轮：弹窗、多选、状态与窄屏（2026-11-23 下午）

前两轮打磨了墙、工具条与详情；这一轮查剩下的界面。

### 9.1 实测问题

| 位置 | 问题 | 原因 |
|---|---|---|
| 用于工作流 | 列出「Token 科普视频 · 已完成」，真实库只有「coffee idea」 | 读的是演示常量 `PROJECTS`，违反数据真实性 |
| 用于工作流 | 弹窗贴在右上角、无遮罩、与详情叠在一起，墙被挤成 3 列 | JSX 用的 `fx-scrim-center` `fx-dialog-head` `fx-dialog-item` 在样式表里不存在，弹窗成了普通块 |
| 导入来源 | 背后整页重度模糊 | 第二轮只给详情换了轻遮罩 |
| 导入来源 | 「识别规则」是居中虚线大框 | 看起来像空状态占位，而不是说明 |
| 弹窗关闭 | 读屏文字是英文「Close」 | 共享 Dialog 的 sr-only 文案 |
| 多选 | 选中的卡只多一个小勾 | 整卡没有选中态 |
| 窄屏 860 | 「按分类」单独掉到第二行左侧 | 搜索固定 260px 不收缩 |
| 读取中 | 只有一行字 | 没有骨架，加载完整墙跳出 |

### 9.2 改动

1. **用于工作流**改用共享 `Dialog`（与详情、导入同一套遮罩、焦点、Esc），叠在详情之上。列表用 `useProjects()` 的真实项目：项目名 + 阶段；没有项目时一句话「还没有项目，先在首页新建」；读取中显示「正在读取项目」。顶部说明压成一行灰字：「调用链未接入，只记入本地意向清单，不会执行。」
2. **导入来源**用轻遮罩；「识别规则」改成左对齐的两条要点，无框，放在输入框下方提示之后。
3. 共享 Dialog 关闭键读屏文字改为「关闭」。
4. **多选**：选中卡 2px 强调色内描边 + 画面轻染强调色；未选中卡不变。
5. **窄屏**：搜索 `flex: 1 1 160px`、上限 260px，排序留在第一行。
6. **读取中**：墙位置显示 10 张同尺寸骨架卡，标题区不跳。
