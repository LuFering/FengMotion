# 工作台：需求、修改意见与版本审阅

日期：2026-10-29。分支：`feat/fe-workbench-review-loop`，起点 `deebf49`。工作区含其他开发者未提交改动，本次未覆盖或提交这些改动。本记录为开发验收，不代表用户认可视觉设计。

## 从文档到用户操作

依据《FengMotion产品体验与工作流说明.md》以及项目设计、协作和页面职责规范，工作台的核心任务是：看真实结果 → 指出具体位置 → 表达修改和保留要求 → 找回意见 → 查看新结果并继续调整。

| 文档需求 | 本次落地 | 实际边界 |
| --- | --- | --- |
| §2 保留原文与后续纠正 | 制作要求保留原始需求，追加带时间的纠正记录；每次意见携带当时快照 | 保存在当前浏览器，未同步云端 |
| §4 素材、参考、特效职责不同 | 保留原有上下文/目标区分，参考不冒充生成结果 | Agent 读取与使用仍未接通 |
| §5–6 不强制依次审批 | 空态展示真实制作状态；预览仍从实际运行产物读取 | 演示日志不被当作视频 |
| §7 准确传递位置与保留条件 | 增加选段起止秒数，区域定位还原高亮；特别保留要求随新意见保存 | 不宣称 Agent 已理解或完成修改 |
| §8 问题与版本连续跟进 | 意见可搜索、定位、继续调整、标记已处理、重新打开；真实文件可同步拖动和播放对比 | 用户处理标记与自动检查分离；同路径文件不能冒充两版 |
| §9 审片与技术检查分离 | 旧预览的确认不沿用到新预览；技术检查未执行时明确显示 | 没有新增自动质检、真实渲染或最终交付闭环 |

## 功能与界面

- 顶部“制作审阅”按需打开右栏的修改意见、制作要求、预览版本。常规状态仍以画面和对话为主；Remotion 参数编辑入口保留。
- 修改意见在发送时保存独立快照，包含项目、原文、纠正、特别保留、目标版本、秒数、结束秒数、区域和上下文。改变输入区设置、追加纠正，不会改写已发送意见。
- 本地记录按项目隔离；保存失败显示仅页面有效，支持导出带项目 ID 的 JSON 备份。此处不把演示任务的会话记录说成已服务端保存。
- 用户可以手动标记已处理并关联当时查看的预览；该动作不触发“检查通过”，演示执行完成也不自动解决意见。
- 版本面板只能选择当前项目真实存在的媒体；两份不同文件、同类媒体可比较。视频对比共享秒数和较短时长，可暂停、拖动、专注画面，再针对其中一份提意见。它不保证两段不同剪辑的内容语义在同一秒对应。
- 加载失败提供重试，不回退旧片。不可用或未加载媒体的帧、区域、选段操作禁用。
- 停止的请求可带回对话，保留原目标和条件，由用户编辑后再次提交。失败请求复用相同恢复入口，但没有制造后端故障来冒充完整异常验收。
- 调整无画面的需求准备区、操作文字、面板层级、字号、素材缩略、三栏比例与局部滚动。使用现有主题变量，不重绘其他页面。
