# 对话区：接入服务层，回复流按契约走

日期：2026-10-29。分支：`feat/fe-workbench-review-loop`。依据《FengMotion产品体验与工作流说明.md》第 2、3 节。
本记录为开发验收，不代表用户认可视觉设计。

## 为什么是「接入」而不是「改样式」

`docs/dev/前后端协议.md` 第 1 条规定**唯一数据入口**：视图只经 `src/services/` 取数与执行动作，禁止视图内散落请求与数据拼装。
而对话区此前是在 `Conversation.tsx` 里用本地函数 `demoReply` 直接编回复——正是该条禁止的写法，也接不上后端。

本轮按 `docs/contracts/agent.md` 把对话能力落成服务接口 + 演示适配器，视图改为只订阅流；适配器将来换成真实后端时视图不动。

## 落地内容与文档对照

| 文档要求 | 本次落地 | 实际边界 |
| --- | --- | --- |
| §2 保留用户原始输入，不被摘要替代 | 用户消息原文原样入库与显示；需求确认卡始终呈现原文，后续纠正是追加而非回改 | 仍只存内存，未落盘 |
| §2 已有信息不重复询问 | 演示适配器按字面读文，**只问原文里确实没有的项**；原话里已写明的时长/画幅/感觉不再问 | 读文是字面规则，不是模型理解 |
| §3 用户能看到方向并确认或纠正 | 对话尾部「需求确认」卡：原文、后续补充、逐条附原文引用、仍缺项；确认后收起并在对话留痕 | 「画面构想」如实标注需要模型，未用模板冒充 |
| §6 不得假装已发送 | 消息落不下去时标记失败并给出原因；流中断不当作完成 | 附件暂不提交（契约要求先上传为 Asset，上传未接入） |
| 演示与真实能力区分 | 每条演示回复带 `demo` 标记，界面显示「演示回复 · 未连接 Agent」；工作台对话页签同样显示 | 未接 Agent 后端 |

## 未验证范围与风险

- **未接真实 Agent**：回复是本地按字面规则拼出的，不是模型生成；§3 的「画面构想」目前是一句「需要模型产出，当前未接入」，**没有**编造分镜文字顶上。
- **失败态分支未真实触发**：演示适配器不会报错，`.cv3-failed` 只验证了样式渲染与「断线不算完成」的服务层行为。
- **会话持久化未接入**：刷新即回到初始状态；也仍存在两套会话存储（适配器的会话接口已实现，左栏会话树仍归 `shell/useSessions`）。
- **附件不随消息提交**：契约要求附件先上传为 Asset 再以 `fileId` 引用，上传能力未接入，因此不拿 `size=0` 与假 MIME 冒充。
- 未验证所有键盘辅助技术、移动端、长会话滚动与服务端同步。
