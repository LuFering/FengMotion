# 怎么用卡库（方法，不是清单）

> 这里不提供"某题材该用哪几张卡"的清单——那是给某一条片子量身定做的，
> 换一个题就不成立。这里只写**怎么找、怎么看、怎么搬**。

---

## 0. 先花 30 秒扫一遍（别一上来就写代码）

```bash
python3 ~/AIremotion-skill/03-工具/search-craft.py --index     # 157 张卡：名字 | 时长 | 一句话
```

一次输出 157 行，扫一遍就知道"库里大概有什么"；再挑 5–8 张打开 demo。
组件库同理：`03-动效组件库/06-动效库/00-跨库总索引.md`。

> 这一步很便宜（一次命令、约 160 行），但它决定后面是"搬"还是"从零写"。
> 上一轮实测：没扫、没读，直接自研，最后剧本里的卡名是编的。

---

## 1. 三种找法（按你手上有什么选）

| 你有的 | 怎么搜 | 例子 |
|---|---|---|
| 一个**动作** | 用手法词搜卡 | `search-craft.py 数字滚动 对比 --only cards` |
| 一个**结构** | 按类目翻：入场 / 转场 / 节奏 / 数据 / 收尾 | `ls 02-镜头卡库/video-shotcraft/gallery/source` 按前缀分组 |
| 一段**参考画面** | 在三个参考视频里按语义搜，再抽帧看 | `search-craft.py 算力 成本 --only ref` |

> 卡库是按**手法**写的，不是按旁白名词写的。
> 搜"平台/背后"多半没结果，搜"对比/揭示/滚动/开门"才有。

---

## 2. 读 demo 源码，只找三件事

卡描述只是索引，参数在 `.tsx` 里。

1. **时长与节奏**：整个动作多少帧？几个阶段？每段多少帧？
2. **幅度**：位移多少 px / 缩放多少 % / 亮度变化多少——换算成"每秒"。
3. **缓动与停顿**：用什么 easing？在哪里停？停多久？

把这三个数抄下来，才是"取材"；只写卡名不算。

---

## 3. 搬结构，不搬皮

> 组件库的组件通常依赖 `remotion-scenes/src/common`（colors/easing/fonts/utils）。
> 复制组件时要把 `common` 一起带上，否则 import 会断。

- 搬：阶段划分、时长比例、缓动、停顿位置、层级关系；
- 不搬：配色、字体、具体图形、品牌元素；
- 改完要能回答：**遮住字幕，这一镜还在动吗？还有信息吗？**

---

## 4. 取材记录（每镜一份，贴在镜头文件头）

```ts
// 取材：卡 <卡名> ← <demo 路径>（抄：<阶段1> <帧数> / <阶段2> <帧数> / easing <曲线>）
// 取材：组件 <组件 .tsx 路径>（抄：<参数名> <值>）
// 取材：参考 <视频文件名> @<时间码>（抽帧 <png 路径>）
```

三条硬要求：

1. 卡名必须能在 `gallery/source/<卡名>.md` 找到；
2. demo 路径必须存在；
3. 「抄：」后面必须是**具体的数或参数名**，不能写"参考了节奏"。

> 写不出这三条 = 没看，不是"没有合适的卡"。
> 如果确实没有合适的卡，就明写「本镜自研，看过 <卡A> / <卡B>，不适用因为 <原因>」。

---

## 5. 什么时候该自研

只有三种情况：

- 卡库 + 组件库 + 参考里都没有对应手法（要举证看过哪几张）；
- 有对应手法，但引擎不兼容（例如卡是 React，你在做纯 HTML）；
- 这一镜的核心创意必须原创（要写清"原创在哪一层"）。

**"懒得找"不算理由。**
