# 桌面打包与自动更新

应用自带后端与 Java 运行时，用户装上即可用 —— 不需要装 Java，也不需要开终端跑后端。

## 打包出的东西

```
FengMotion-<版本>-x86_64.AppImage        可分发的单文件应用（约 230MB）
release/latest-linux.yml                 更新清单（含 blockmap 差分信息）
release/linux-unpacked/resources/
  ├── jre/                               裁剪过的 JRE（54MB）
  └── backend/fengmotion-server.jar      后端（38MB）
```

完整 JDK 约 300MB，用 `jlink` 裁剪到 54MB。需要的模块清单不是猜的 —— 见下面「踩过的坑」。

## 常用命令

```bash
npm run desktop:resources   # 只准备 jar 与 JRE（不打包）
npm run desktop:dist        # 完整打包 AppImage
npm run desktop:release     # 打包并发布到 GitHub Releases
```

## 后端如何随应用启动

主进程（`electron/main.ts`）在 `app.whenReady()` 里调用 `startBackend()`：

1. 定位 `resources/jre/bin/java` 与 `resources/backend/fengmotion-server.jar`
2. 选端口：优先 8080，被占用则向系统要一个空闲端口
3. spawn 后端，把数据目录指到 `app.getPath('userData')/data`
4. 轮询 `/api/health` 直到就绪（最长 60 秒）
5. 把实际 `apiBase` 传给前端
6. 应用退出时（`before-quit`）先 SIGTERM 优雅停后端，5 秒未退则 SIGKILL

后端启动失败**不阻止开窗** —— 前端仍可浏览，只是 Agent 不可用。

## 增量更新

用 `electron-updater` + GitHub Releases。AppImage 内嵌 blockmap，更新时只下载变化的块而不是整包。

- 只在打包态启用（开发态跑了会把 GitHub 上的产物覆盖到开发目录）
- `autoDownload = false`：先提示再下载，避免创作中途占带宽
- `autoInstallOnAppQuit = true`：下次退出时自动装
- 更新失败只记日志，不弹窗打断用户

## 踩过的坑（都会导致「打不开」）

| 现象 | 原因 | 修法 |
|---|---|---|
| 应用启动即崩 `Cannot find module './backend'` | 打包进 asar 后，`require('./backend')` 不会自动补 `.cjs` 扩展名 | 构建脚本里把 require 路径显式改成 `./backend.cjs` |
| 后端起不来 `NoClassDefFoundError: org/ietf/jgss/GSSException` | jlink 裁剪漏了 `java.security.jgss`，Tomcat 认证链路要用 | 模块清单补齐 jgss / sasl |
| 数据库写到奇怪位置甚至启动失败 | `jdbc:sqlite:./fengmotion.db` 是相对路径，打包后工作目录不确定 | 改成 `--fengmotion.data-dir` 传入绝对路径 |
| 8080 被占用时应用完全打不开 | 端口硬编码 | 启动时探测空闲端口 |
| 打包应用双击没反应 | 已有旧实例在跑，单实例锁生效 | 先退出旧实例 |

## 平台现状

当前只配置了 Linux AppImage。Windows / macOS 需要在 `electron-builder.config.mjs` 里加 `win` / `mac` 段，并各自准备对应平台的 JRE（jlink 交叉裁剪不支持，须在目标平台构建）。
