# FengMotion 页面职责合同

> 版本：v2 · 2026-10-22 · 基线 `ee1b35f`
> 配套《UI实现规范》（合同解决"页面干什么"，规范解决"页面长什么样"）。
> 性质：**产品合同**，不是设计稿。界面改造按 01–06 期推进（见《FengMotion 前端下一步开发计划》）。

| 改动 | 说明 |
|---|---|
| 十个页面 → **八个** | 内容编排中心、时序校验中心、资源接入与解析中心、反馈与规则中心、流程与质量保障中心、项目指挥中心，六个页面已在 `be98d3b` 下线；「创作资产中心」并入「我的素材」 |

## 一、统一状态模型（所有页面共用）

界面上出现过的"规格冒充已解析""点了停用没反应""移除后计数不变"，根因都是把下面这些状态压成了一个 `ready`。

### 1.1 资源状态模型（五个维度正交，不是一个字段）

v1 曾把"已确认/已应用/已停用"压成一条互斥生命周期链，这是错的——一项特效被三个项目引用，它仍处在"已确认可用"。

| 维度 | 回答什么 | 取值 |
|---|---|---|
| **来源类型** | 从哪来 | 内置资源 / 用户导入 / 示例数据 |
| **处理状态** | 处理到哪一步 | 待解析 / 解析中 / 解析完成 / 解析失败 |
| **审核状态** | 人确认过吗 | 未产生 / 待审核 / 已通过 / 已驳回 |
| **可用状态** | 现在还能用吗 | 启用 / 停用 / 弃用 |
| **引用关系** | 被谁用了 | 项目 / 场景的引用列表（多值，不是状态） |

示例组合：
- 内置特效：来源=内置资源 · 审核=已通过 · 可用=启用 · 引用=3 个场景
- 新上传视频：来源=用户导入 · 处理=待解析 · 审核=未产生 · 可用=启用 · 引用=无
- 已停用特效：审核=已通过 · 可用=停用 · 引用=保留历史引用（不允许新的应用操作）

**合法转换**
```
来源类型：导入即确定，不可变
处理状态：待解析 → 解析中 → 解析完成 | 解析失败
          解析失败 → 待解析（可重试）；解析完成 → 待解析（重新解析）
审核状态：解析完成 → 待审核 → 已通过 | 已驳回
          已驳回 → 待审核（修订后可再提）
可用状态：启用 ⇄ 停用；启用|停用 → 弃用（终端）
引用关系：任意时刻可增删；可用=停用 时禁止新增引用，保留已有引用
```

**非法转换（界面必须阻止或置灰）**
- 未"解析完成"就进入"已通过"
- 可用=弃用 后回到启用
- 可用=停用 时新增引用
- 把"已应用"当状态的终态（它是引用关系）

**删除/停用的连带规范**
1. 移除资源：先从所有引用中摘除（或阻止并列出引用方），再移除本体
2. 停用资源：保留引用与历史，禁止新增引用；下游列表默认隐藏，可切换"显示已停用"
3. 所有派生统计（列表计数、分类计数、来源计数、预览数）必须由同一份可见集合计算
4. 移除当前选中项后，选中下一个可见项；没有可见项时进入空态并清空详情
5. 任何写操作若不会持久化，必须在**操作前**让用户知道（不只是角落一行提示）

### 1.2 交付物状态

```
未组装 ──► 组装中 ──► 可交付 ──► 已交付
   │                     │
   └─► 缺件（列出缺什么）  └─► 验收未通过（列出未通过的判据）
```

- 未组装时**不给下载按钮**，而是列出还缺哪些组装步骤/验证条件。
- 云渲染未接入时，展示真实已有的成片与可交付状态；渲染动作置灰并写"云渲染未接入"。

### 1.3 未接入能力的统一表达

| 能力 | 界面表达 | 动作状态 |
|---|---|---|
| 视频拆解 / 参考片分析 | 新导入的参考片停在「待解析」 | 「开始解析」置灰，旁注"解析未接入" |
| ASR（口播对齐） | 只给估算值，不给判定 | 「识别对齐」置灰，旁注"ASR 未接入" |
| 云渲染 | 只展示真实已成片 | 「渲染」置灰，旁注"云渲染未接入" |
| Agent 执行 | 任务记录明确标「演示数据 · 未连接 Agent」 | 提交只入队，不承诺产出 |
| 质量检查执行 | 未执行 ≠ 通过；示例数据必须标 Demo | 「开始检查」置灰或标演示 |
| 落盘 | 写操作标注「仅本次会话有效」 | 正常可用，结果不承诺保留 |

**原则**：按目标形态画出来，把"为什么现在不能用"写成一句人话，而不是隐藏按钮或假装能用。

### 1.4 术语表（消灭内部黑话）

| 不要用 | 统一为 | 说明 |
|---|---|---|
| 镜头卡 / 卡库 / 创作技法库 | **特效**（页面叫「特效库」） | 通用层不出现"镜头"这类范式词；页面名以代码与导航为准 |
| 视频库 | **参考片库** | 主体是真实参考视频 |
| 片型画像 / 规格 | **片型画像** | 与"参考片"是两种对象，不得混标状态 |
| 样片 | **预览动效** | |
| 判例 / 规则 | **检查项**（06 期后） | 一条原话 ≠ 一条通用规则；规则能力收进工作流，不再单独成页 |
| Unit / 单元 / 制作单元 | **场景** | 工作台与项目数据统一叫法 |
| 草稿时间轴 | **脚本时间轴** | 与"成片时间轴"相对 |
| 未落盘 / 内存里 | **仅本次会话有效** | |
| 后端未接入 | **解析未接入 / ASR 未接入 / 云渲染未接入** | 指名道姓，不要笼统说"后端" |
| 复刻页 / iframe 页 | **过渡页** | 工作流、发布与验收、项目总览三处 |

### 1.5 核心对象与边界（一个对象只承担一种意义）

| 对象 | 职责 | 不得混用 |
|---|---|---|
| 项目 | 创作目标、阶段、产物、状态 | — |
| 场景 | 具体内容、执行结果、验收状态 | — |
| 素材 | 真实文件、元数据、使用关系 | — |
| 特效 | 可复用表现方式、参数、适用条件 | — |
| 参考片 | 有来源、有证据的学习材料 | 不得与「片型画像」混标 |
| 片型画像 | 对某类作品的抽象描述（节奏/构成/出镜比例） | 不得冒充"已解析视频" |
| 工作流 | 制作方案：节点、连线、参数、版本 | 不得与「一次运行」混用 |
| 工作流运行 | 一次执行的实例：runId、状态、节点输入输出 | 不得当模板本身 |
| 检查运行 | 一次质量检查：checkRunId、范围、结果 | 不得当检查项定义 |
| 检查项 | 一条可定位的问题：严重程度、目标、修复建议 | 不得与"用户已处理"混为一谈 |
| 交付物 | 版本、生成状态、可用文件 | — |

### 1.6 能力依赖四分类（不得把"界面能做出来"当成"功能已完成"）

| 类别 | 含义 | 界面要求 |
|---|---|---|
| **A 纯前端可实现** | 无需新数据、无需持久化 | 直接做，真实生效 |
| **B 现有真实数据可实现** | 数据在仓库里，只是没接进这个页面 | 直接做，数据必须是真的 |
| **C 需要持久化支持** | 交互能做，但结果存不下来 | 界面做出来，**操作前明确告知不会保存** |
| **D 需要新增后端能力** | 解析 / ASR / 云渲染 / Agent / 检查执行 | 按目标形态画出来，动作置灰并写明"XX 未接入" |

当前八页归类（随实现推进更新）：

| 页面 | 主要依赖 | 备注 |
|---|---|---|
| 首页 | A | 创作提交属 C（任务只入队） |
| 我的创作 | B（项目列表、阶段、封面） | 搜索/筛选/排序属 A |
| 制作工作台 | B（场景、成片、抽帧、任务记录） | 执行属 D；Gate 确认属 C |
| 工作流 | B（模板与画布在复刻页内） | 保存/运行联动属 C+D |
| 特效库 | B（技法数据与预览素材已有） | 用于工作流属 C |
| 参考片库 | B（21 个镜头段与十维分析已有） | 上传解析属 D |
| 我的素材 | A（导入与索引真实生效）+ D（解析） | 新导入一律停「待解析」 |
| 发布与验收 | B（成片文件真实可下） | 检查执行属 D；云渲染属 D |

## 二、八个页面的职责合同

每页八项：**目标用户 / 主要任务 / 核心对象 / 帮用户决定什么 / 主要操作 / 完成后下一步 / 与现状的差距 / 硬规则**。

### 1. 首页

| 项 | 内容 |
|---|---|
| 目标用户 | 刚打开产品、准备开始或继续创作的人 |
| 主要任务 | 用一句话开始创作 / 继续最近的项目 |
| 核心对象 | 创作请求（自然语言）、最近项目 |
| 帮用户决定的事 | **我现在要做什么？** |
| 主要操作 | 写一句话提交、粘贴脚本、附参考素材、点最近项目继续 |
| 完成后下一步 | 提交后创建任务并进入工作台 |
| 与现状的差距 | 首屏已成型（`home-film.css`，锁一屏不滚动）；缺「最近项目 2–4 个」与提交后的任务创建 |
| 硬规则 | 不做后台仪表盘；不做全量项目列表；Demo 提交必须明说不会真的建任务 |

### 2. 我的创作

| 项 | 内容 |
|---|---|
| 目标用户 | 手上有一个或多个视频任务的人 |
| 主要任务 | 找到要继续的那个任务 / 判断它现在卡在哪 |
| 核心对象 | 项目（名称、封面、阶段、最近活动、目标时长） |
| 帮用户决定的事 | **我该继续哪一个？它现在需要我做什么？** |
| 主要操作 | 搜索项目名、按状态筛选、按最近修改排序、点卡进入工作台 |
| 完成后下一步 | 进入该项目的制作工作台 |
| 与现状的差距 | **基本没做**：目前只有一个裸网格（`.fm-project-grid`），页头/工具栏/状态筛选/排序都没有；项目总览（callour iframe）的有效信息要并进来 |
| 硬规则 | 每张卡只展示**一个**最重要的状态（生成中/需要确认/检查有问题/已完成/生成失败）；Demo 数据必须标明；状态用用户能懂的下一步说法，不用技术状态 |

### 3. 制作工作台

| 项 | 内容 |
|---|---|
| 目标用户 | 正在制作某个视频的人 |
| 主要任务 | 看当前场景 → 让 Agent 改 → 确认结果 |
| 核心对象 | 场景、监看器时间点、对话记录、任务记录、产物 |
| 帮用户决定的事 | **这一版能接受吗？不能的话改哪里？** |
| 主要操作 | 选场景、播放/定位、和 Agent 对话下指令、改参数、看执行过程、处理 Gate 确认 |
| 完成后下一步 | 进入发布与验收；或继续下一场景 |
| 与现状的差距 | 三栏骨架已成型；缺 Gate 确认卡、检查问题定位、失败恢复；右栏实际只有 3 个页签（场景/对话/参数）而非计划里的 5 个 |
| 硬规则 | **唯一使用三栏骨架的页面**；四状态（正常创作/等待 Gate/执行失败/检查有问题）必须都能走通；监看器宽度不低于 480px |

### 4. 工作流

| 项 | 内容 |
|---|---|
| 目标用户 | 想复用或定制一套制作方案的人 |
| 主要任务 | 找模板 → 看它要什么 → 用起来 / 改节点 |
| 核心对象 | 工作流定义（节点/连线/参数/版本）、工作流运行（runId/状态/节点 IO） |
| 帮用户决定的事 | **这套方案适合我这个片子吗？需要改哪几步？** |
| 主要操作 | 浏览模板、看详情（用途/输入要求/输出类型/版本）、从详情建任务、编辑节点与连线、保存 |
| 完成后下一步 | 带着输入配置进入工作台 |
| 与现状的差距 | 整个页面是 15.7MB 的 iframe 复刻（28 处 base64 内联），与壳两套语言；05 期分四阶段原生化 |
| 硬规则 | 达到第 7 节五项删除验收前**不删 iframe**；演示执行如实标 Demo |

### 5. 特效库

| 项 | 内容 |
|---|---|
| 目标用户 | 想找一种表现手法并用到当前创作的人 |
| 主要任务 | 找到效果 / 判断适不适合 / 用起来 |
| 核心对象 | 特效（解决什么表达问题、适用场景、需要什么输入、实现方式、参数、限制） |
| 帮用户决定的事 | **这个效果解决我的问题吗？怎么用？** |
| 主要操作 | 搜索、按用途分类、筛选、看预览、看实现与参数、复制配方、用于工作流 |
| 完成后下一步 | 进入工作流的对应节点应用 |
| 与现状的差距 | 现在是「三组技术筛选 chips + 表格列头 + 属性抽屉」，服务的是查数据；04-B 期改成效果预览卡片网格 |
| 硬规则 | 分类按**效果用途**组织（转场/镜头运动/文字…），不按实现技术；「用于工作流」只在真实调用链可用时启用，否则点开是目标选择弹窗，不假装可用 |

### 6. 参考片库

| 项 | 内容 |
|---|---|
| 目标用户 | 要从已有作品里学做法的人 |
| 主要任务 | 研究参考片 / 定位某个镜头段 / 提取可复用做法 |
| 核心对象 | 参考片（真实文件、时长、关键帧、镜头段、十维分析、引用位置）、片型画像 |
| 帮用户决定的事 | **我能从这段片子里借鉴什么？用在哪？** |
| 主要操作 | 按风格/用途筛选、看卡、点镜头段定位播放、看十维分析（摘要→完整→依据三层）、用于创作 |
| 完成后下一步 | 进入特效库找对应技法；或进入工作台应用 |
| 与现状的差距 | 卡片网格已成型（21 个镜头段，带分析状态）；缺播放器与镜头段时间线联动，详情还是普通抽屉 |
| 硬规则 | 十维分析必须分层呈现，主视图不铺满分析字段；**观察事实与模型推断必须分开**，不把推断包装成事实；关键帧或分析缺失时显示明确状态，不虚构内容 |

### 7. 我的素材

| 项 | 内容 |
|---|---|
| 目标用户 | 需要管理真实文件、并把它用到创作里的人 |
| 主要任务 | 导入 / 找到文件 / 用到创作里 |
| 核心对象 | 素材（真实文件、类型、时长尺寸、授权、审核、引用项目） |
| 帮用户决定的事 | **这份素材能不能用？它被谁用了？** |
| 主要操作 | 拖放导入、搜索文件名/类型、按类型与位置筛选、看详情、加入创作、多选批量操作 |
| 完成后下一步 | 进入工作台对应场景使用 |
| 与现状的差距 | 网格 + 抽屉 + 导入已可用；缺导入失败原因与重试、引用情况展示、"解析为参考片"入口 |
| 硬规则 | 授权与审核**分离**，未确认一律 unknown；删除前检查引用；不强制每个上传视频自动 AI 分析；普通视频与已解析参考片归属不得混淆 |

### 8. 发布与验收

| 项 | 内容 |
|---|---|
| 目标用户 | 要交付成果的人 |
| 主要任务 | 判断能不能交付 / 处理未通过项 / 导出 |
| 核心对象 | 交付物（版本、生成状态、可用文件）、检查运行、检查项、缺失项 |
| 帮用户决定的事 | **现在能不能交付？不能的话缺什么？** |
| 主要操作 | 看检查结果、看缺件清单、定位问题、返工后复检、下载真实可交付文件 |
| 完成后下一步 | 交付；或回到工作台补齐缺失项 |
| 与现状的差距 | 现在是 iframe 复刻（`qc-preview-v2.html`，内容是示例数据），06 期接真实检查数据后原生化 |
| 硬规则 | 未检查**不显示通过**；技术检查与内容/叙事检查分组呈现，叙事类必须结合渲染预览或关键帧审查，不得只查源码就宣称通过；用户标记「已处理」≠ 检查通过，两者在数据与 UI 上分离 |

## 三、导航现状

```
侧栏（6 项，扁平）
  首页 · 我的创作 · 工作流 · 特效库 · 参考片库 · 我的素材

项目内（2 项，不进侧栏）
  制作工作台 · 发布与验收

过渡页（3 处 iframe，按 05/06 期逐步原生化）
  工作流 · 发布与验收 · 项目总览（去向见开发计划 §4.8）
```

- 顶部标签栏（`.tabbar`）与侧栏重复，**已确认删除**（当前 `display: none`，属死代码，01 期清掉）。
- 不设二级分组。v1 的三级分组方案（项目与交付 / 创作资源 / 规则与质量）不采用。

## 四、验收标准（改完之后怎么判断成了）

| 维度 | 成功标准 |
|---|---|
| 页面定位 | 每页都有独立且清晰的主要任务；解释不出独立价值的页面已合并或取消 |
| 操作闭环 | 用户能完成主要任务，并知道结果与下一步，而不是只浏览 |
| 页面协作 | 特效、素材、参考片、工作流、项目之间能建立实际关联与跳转 |
| 状态真实性 | 不存在按钮无效、状态假成功、统计口径冲突、规格冒充真实产物 |
| 信息组织 | 先给"作决定所需的信息"，再给详细参数/来源/技术信息 |
| 完成度分层 | **UI 完成 ≠ 交互连通 ≠ 真实能力完成**，三者不得用同一个"已完成"代替 |
| 可扩展性 | 更换制作范式时，不需要重写通用层的项目管理、素材与质量治理 |
