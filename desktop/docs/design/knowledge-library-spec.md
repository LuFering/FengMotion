# 知识库规范（knowledge-library-spec）

> 参考片库、特效库、我的素材是**三套不同的界面与数据模型**。
> 共用：搜索框、标签组件、卡片基础样式、详情抽屉。
> **不共用**：页面模板、数据模型。

## 一、三库差异总表

| | 参考片库 | 特效库 | 我的素材 |
|---|---|---|---|
| 类型 | 视觉探索型 | 技法目录型 | 文件管理型 |
| 回答 | 有什么值得借鉴 | 用什么方法实现 | 有哪些文件可以用 |
| 主要动作 | 发现、比较、分析、引用 | 理解、测试、组合、复用 | 导入、查找、整理、选择 |
| 主参考 | ShotDeck + Motion Index + Cosmos + Fabric | Kive + ComfyUI 参数体验 | Kive 资产组织 |
| 内容单元 | 参考片 → 片段 → 镜头分析 | 技法（效果+实现） | 文件（实体+元数据） |

## 二、参考片库（视觉探索型）

**不要做成只有封面、标题、标签的收藏夹。**

页面结构：
- 以视觉内容为中心的**卡片网格**（大图/视频预览优先）
- 组织单元：视频、关键帧、片段、收藏集
- 筛选维度：风格、构图、镜头类型、运镜、节奏、转场
- 语义搜索 + 相似镜头入口
- 视频预览 + **时间码定位**
- 可把参考片段**拖进创作任务**

镜头分析详情（点开一个片段）：
- 构图、摄影机运动、剪辑节奏、转场、光影、色彩、视觉风格、叙事作用
- **分析证据、置信度、人工修正记录**（数据真实性契约：未分析的维度显示「未分析」）
- 关联：关联参考片、关联技法、引用到工作流

数据模型要点：`参考片(id) → 片段(id, 时间码) → 分析结果(维度, 证据, 置信度)`，
分析结果可被工作流的「参考片检索」节点按维度检索。

## 三、特效库（技法目录型）

现有基础：157 张技法卡（`src/data/knowledge`，字段 id/cat/name/…/poster/motion）。
改造方向：从「卡片目录」升级为「制作方法库」。

每项技法应包含：
- 效果名称、预览（poster/motion）、分类、适用场景
- 制作原理、实现步骤
- 输入要求、参数及默认值
- 所需工具、模板、代码或提示词
- 依赖条件、限制、失败案例、替代方案
- 关联技法、关联参考片段
- **可执行状态**及测试结果
- 操作：添加到工作流、在指定输入上测试

**铁律**：必须区分「知识描述」与「真正可执行的实现」——
没有可调用工具或实现方案的技法，不得显示为已支持自动执行（灰显+注明）。

## 四、我的素材（文件管理型）

独立的文件管理界面：
- 类型：图片、视频、音频、字体、模板、生成文件
- 操作：上传、文件夹、搜索、排序、筛选
- 视图：网格 / 列表双模式
- 元数据：缩略图、文件类型、尺寸、时长、文件大小
- 单文件：预览、批量选择、重命名、删除、**引用位置**（被哪些任务/工作流使用）
- 与任务衔接：从工作流或创作任务中选择素材

现有可复用：`VideoLibrary` / `KnowledgeSources` 的真文件解析
（`readVideoDuration`、`fmtSize`、`guessKind`）；导入不再单独占页面（并入本库）。

## 五、关联与 ID 约束（跨库）

- 为参考片、片段、技法、工作流节点、素材设计**稳定关联 ID**。
- 检索结果必须能追溯到来源片段或技法条目。
- 素材被引用时记录引用位置；删除有引用的素材需要提示。

## 六、诚实性约束（沿用数据真实性契约）

- 未接入能力：灰显 + 注明原因（`解析未接入` / `ASR 未接入` / `未分析` 等模式）。
- mock 数据明确标注来源；不伪造「已解析/已分析/已生成」。
- 导入/分析/生成类操作必须有进行中态与失败态。

## 七、验收标准（阶段三）

- 三库页面结构、数据模型互相独立（不出现同一个模板套三遍）。
- 检索、筛选、详情、关联操作可用；未接入能力灰显注明。
- 稳定 ID 就位；检索可溯源。
- `npx tsc -b` + `npm run build` 过；界面改动附真实截图。
