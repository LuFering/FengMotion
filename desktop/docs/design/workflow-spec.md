# 工作流产品规范（workflow-spec）

> **三个互相关联的页面，而不是一个巨大的节点编辑器。**
> 广场（发现方案）→ 编辑器（定制逻辑）→ 使用页（生产视频）
> 2026-10-16 按作者提供的新界面文档重写（原两页结构作废）；
> 画布技术底座 React Flow，执行调试参考 Dify / Langflow / n8n。

## 一、概念模型（先分清两件事）

| | 工作流定义 | 创作任务 |
|---|---|---|
| 是什么 | 可长期保存/复制/编辑/复用的制作方案 | 某次具体的视频制作 |
| 生命周期 | 长期演进，有版本 | 一次执行，有状态（进行/等待/完成） |
| 记录 | 节点、连线、配置、提示词、检索范围 | 所用**工作流版本**、输入、执行过程、产出 |
| 铁律 | 修改工作流**不得**悄悄改变已运行任务的定义 | 任务必须记录执行时的工作流版本快照 |

## 二、页面 A · 工作流广场

**任务**：浏览不同制作方案，找到适合的开始。
**展示每条工作流**：预览（节点结构 / 产出示例）、用途与适用场景、输入要求、
预期产出、适用人群、最近更新时间。
**功能**：分类（科普视频 / 产品广告 / 参考片复刻 …）、搜索、从模板复制、
创建空白工作流。
**形态**：卡片网格，视觉预览优先，不是纯文字列表。
**参考**：Runway 工作流模板 —— 让创作流程（而非技术配置）成为用户的中心。

## 三、页面 B · 工作流编辑器

**任务**：编辑完整制作逻辑（给需要控制全流程的人）。
**布局**（四区）：

```
顶栏：工作流名 · 版本 · 保存状态 · 试运行 · 返回广场
├────────┬──────────────────────────┬──────────────┤
│ 节点库  │        画布               │   节点检查器  │
├────────┴──────────────────────────┴──────────────┤
│ 执行与调试：节点顺序 · 输入输出 · 日志 · 耗时 · 重试 │
└──────────────────────────────────────────────────┘
```

**节点类型**（第一期）：开始 / 结束、输入、LLM、参考片检索、特效检索、
素材选择、视频生成、质量检查、条件分支。
**节点卡片**：显示**真实媒体输入输出**（视频/图片/检索结果可预览）、执行状态、
错误摘要 —— 不做只有抽象图标和文字的节点。
**交互**：增删、连线、配置、复制、删除、撤销重做、自动布局、保存版本、
复制工作流；**单节点测试、局部重跑**。
**调试**：节点输入输出、错误原因、耗时、**历史运行记录**（参考 n8n 执行管理）。
**参考**：Runway（创作逻辑）+ InvokeAI（编辑器与 Workflow Library）。
**技术**：`@xyflow/react` 12.x 为画布底座（peer 依赖 react>=17，仓库 React 19.2
兼容，已核对）；视觉按 `design-system.md` 重做，**不用其默认皮肤**。

## 四、页面 C · 工作流使用页（把工作流变成创作表单）

**任务**：普通用户不进入节点编辑器，也能用这条工作流生产视频。
**表单只暴露**：创作目标、素材上传、参考片选择、风格偏好、少量高级选项。
**不暴露**：内部节点配置。
**运行后**：执行进度、中间结果、最终成片、继续修改入口。
**参考**：InvokeAI Linear View（复杂节点图 → 简单表单）+ Figma Weave Tools
（编辑模式 / 使用模式两种界面）。
**铁律**：普通用户使用工作流**不应被迫进入节点编辑器**。

## 五、三页导航与状态关系

```
广场 ──复制 / 开始使用──▶ 使用页 ──运行──▶ 进度 → 结果 → 继续修改
 │                          ▲
 └──编辑──▶ 编辑器 ──保存版本──┘（版本号递增）
              │
              └── 试运行（结果不进任务记录）
```

- 使用页提供「深入定制」入口 → 编辑器（当前工作流）。
- 编辑器保存后版本递增；使用页始终显示所用版本。
- 试运行不进入任务记录；正式运行进入「我的创作」。

## 六、数据模型（草案，实现时可调）

```ts
/** 工作流定义 —— 可保存/复制/编辑/复用 */
interface WorkflowDef {
  id: string                    // 稳定 ID
  name: string
  description: string
  purpose: string               // 适合做什么类型的视频
  version: number               // 保存时递增
  origin: 'builtin' | 'mine'    // 内置模板 / 我的工作流
  nodes: WorkflowNode[]
  edges: { id: string; source: string; target: string }[]
  updatedAt: string
}
interface WorkflowNode {
  id: string
  type: 'start' | 'end' | 'input' | 'llm' | 'ref-search' | 'fx-search'
      | 'asset-pick' | 'video-gen' | 'qc' | 'branch'
  position: { x: number; y: number }
  config: Record<string, unknown>   // 按类型定义（提示词/检索范围/参数…）
}

/** 创作任务 —— 某次实际执行 */
interface CreativeTask {
  id: string
  workflowId: string
  workflowVersion: number       // 快照：改工作流不影响已运行任务
  inputs: Record<string, unknown>
  status: 'running' | 'waiting' | 'failed' | 'done' | 'idle'
  runLog: unknown[]             // 节点执行记录（试运行不写入）
  outputs: unknown[]
}
```

稳定 ID 约定：工作流 / 节点 / 参考片片段 / 技法 / 素材都需可被引用与溯源。

## 七、产品原则

1. 工作流是可复用制作方案，创作任务是某次执行，两者必须分离。
2. 编辑器不能只有抽象节点，应充分支持图片、视频、镜头和特效结果预览。
3. 复杂配置放检查器，节点卡片不膨胀。
4. 普通用户使用工作流不应被迫进入节点编辑器。
5. 调试体验必须包含：节点输入输出、错误原因、局部重跑、历史运行记录。
6. 统一视觉语言（`design-system.md`），不复制参考产品的品牌样式。

## 八、诚实性约束

- 后端未实现时用**明确标注的 mock adapter**，不得伪装成真实 AI 执行。
- 不引入未经确认的向量数据库或 LLM 服务。
- 检索到技法卡 ≠ 可自动执行；只有关联了可执行代码/模板/工具的技法才显示「可执行」。

## 九、验收标准

- 广场：分类 / 搜索 / 复制 / 创建全部生效；模板标注为示例。
- 编辑器：拖拽、连线、配置、删除、撤销重做、自动布局、保存全部可用；
  节点媒体预览真实；单节点测试与局部重跑可用（mock 也须真实反映状态流转）。
- 使用页：表单可运行（mock 明确标注）；进度 / 结果 / 继续编辑可用。
- 三页互通（广场 → 编辑器 → 使用页）；版本快照记录正确。
- `npx tsc -b` + `npm run build` 过；界面改动附真实截图。
