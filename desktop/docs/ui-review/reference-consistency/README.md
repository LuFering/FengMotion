# 工作台：引用对象一致性、同位置对比与每轮差异

日期：2026-10-29。分支：`feat/fe-workbench-review-loop`。依据《FengMotion产品体验与工作流说明.md》第 7、8 节。
本记录为开发验收，不代表用户认可视觉设计。

## 这一轮解决的是「用户指的对象 ≠ 实际要改的对象」

第 7 节写明核心不是按钮，而是**用户指的对象与 AI 实际修改的对象是否一致**。审计发现三处会破坏这个一致性的实现问题，以及第 8 节「在相同位置比较」缺失：

| 问题（审计定位） | 处理 |
| --- | --- |
| 不点「引用此帧」直接发送时，`currentPreviewRef` 不带 `timeSeconds`，**时间位置整段丢失** | 默认目标改为带上当前停留秒数（图片不编造 0） |
| 切换预览画面只清框选态、**不清旧 target** → 用户看着 B、提交的仍是 A 的区域引用 | 换画面即把上一画面的区域/时间引用降为上下文，并给出一句提示；context 引用保留 |
| 「背景不要动」只有自由文本，`ModificationConstraints` 里没有对应结构化项 | 新增可选 `preserveOutsideSelection`（本地扩展，未冻结为服务端契约，已记入前后端协议） |
| 对比固定从 0 秒开始、不含区域，做不到「相同位置比较」 | 从「用户指的那一帧」打开：两侧 seek 到同一秒、叠同一个框选区域 |
| 演示适配器只读 target 的 `label`，区域/时间/保留条件/需求快照全部无消费者，用户无从核对 | 适配器逐项回执实际收到的字段；缺项也写明「没有」，不静默略过 |
| 「变更审阅」栏是一句静态「还没有文件变更记录」 | 改为每轮真实输入与上一轮差异，并说明为什么没有文件清单 |

## 未验证范围与风险

- **真实渲染链路未执行**：`renderScene` → WebCodecs 编码没有跑过。工作台画面来源必须是真实产物（`stageVisual.ts` 明确规定占位成片不算来源，演示工作流的产物也不指向媒体文件），所以本次验证**使用了测试夹具**：通过素材库真实导入仓库既有 `public/media/clips/c1.mp4`、`c2.mp4`，并在 `fengmotion:editor-renders:<projectId>` 登记为编辑器导出记录。夹具只让「有画面可引用」成立，两段视频不是 AI 生成结果，也不被当作同一内容的真实修改前后。
- **引用秒数超过某一侧时长时的行为**未验证（代码按各侧自身时长钳制，共享时长取较短值）。
- **`.cv3-failed` 的 React 分支**未触发（演示适配器不报错），只验证了样式渲染与服务层「退订不发 completed」。
- **中间提交未逐一验建**：`tsc` 读工作区而非暂存区，无法在不改动其它文件的前提下按组验证，因此 bisect 到本分支中间某个提交不保证可构建。
- 未验证所有键盘辅助技术、移动端与服务端同步。
