# Film Plan（导演处理）

> 一页导演处理，不是审批表，也不是分镜 schema。
> 多镜头/长片写；单镜头可只写关键画面。
> 它服务于画面，不是让模型填字段。如果写到最后只是在填表，删掉，回到参考和画面。

## 0. 一句话

- 这部片的一句话：
- 视觉命题：
- 观众最后应该记住的一帧：

### 0.1 内容契约

解释/技术/数据类必写；MV/叙事片写体验弧：

- 核心观点/核心体验：
- 支撑它的 2–4 个关键事实/关键画面：
- 关系/顺序：因果 / 递进 / 对比 / 转折 / 并列；
- 每段承担哪个事实/体验：
- 结尾如何收束：
- 观众看完应该能复述的一句话：

写不出“观众应该记住什么”，先不要进入镜头设计。

### 0.2 叙事阶段与理解链

时间顺序不等于发展故事。先按内容归纳 2–4 个有意义的阶段（不固定四段，不能为了戏剧性混事实）：

| 阶段 | 起止 | 观众原本知道什么 | 这一阶段的新事实/视觉证据 | 为什么引出下一阶段 | 阶段结束观众应理解什么 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

- 每个阶段至少回答“新事实 → 视觉证据 → 为什么下一步”；写不出因果，就还是版本列表。
- 阶段内可以有多个版本；不要让每个版本都自动获得一套相同的镜头/卡片。
- 阶段划分必须服从数据/原文，不能把不同能力混为一谈。

## 3. 镜头、动作与时间设计

### 3.0 视觉机制与帧级时间编码

**视觉机制**：一句话写清贯穿全片的可见机制；它必须同时解释内容、镜头和节奏。

**镜头行为**（不是“慢推/电影感”，而是可写成数值/曲线）：

- 相机跟谁/看什么：
- 视点/锚点偏移：
- 旋转/俯仰/滚转：
- 推进/拉远/横移：
- 焦点转移：从谁到谁，何时：
- 何时停、停多久：
- 这个行为如何服务视觉机制：

如果输入有 BPM/节拍，先换算：`节拍 → 帧 → 段落边界`；
没有节拍就用秒/帧写清起止。写不出数值/曲线的镜头行为，还没有被设计。

> 先写成帧号/时长/曲线，再写代码。渲染只验证不可计算项。

**视觉语义**（最多 5 行；元素必须在实际镜头里产生对应变化，不能只写文档）：

| 视觉元素 | 承担的意义 | 必须让观众看见的变化 |
|---|---|---|
| 主发展线 | 技术/叙事主线 | 从起点连续推进到新阶段 |
| 节点/形态 | 关键突破 | 新能力改变原有结构 |
| 分支/汇聚 | 扩展/整合 | 路径关系发生可辨认变化 |
| 数据图形 | 对比/规模 | 先建立比较，再突出结果 |
| 最终图形 | 结论/记忆点 | 前面机制汇聚、转化或完成 |

**整片镜头差异预算**（不是逐镜填表）：

- 必须连续的元素：主发展线 / 材质 / 色板 / 运动语言；
- 必须改变观看体验的位置：景别 / 视点 / 空间层次 / 信息形式，至少一项实质变化；
- 只是为了“看起来不同”的变化：删掉；
- 连续两个版本场景使用同一构图/同一观看位置，就要重想其中一个。

| 段落 | 场景类型 | 新信息 / 视觉证据 | 视觉权重 | 观看任务 | 时长/拍 | 镜头设计（景别/视点/空间层次/运动目的） | 镜头衔接 / 结束状态 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |

场景类型示例：开场钩子 / 规模展示 / 数据对比 / 对抗 / 快闪 / 高潮 / 收束。
视觉权重示例：铺垫 / 过渡 / 重点 / 高潮。
观看任务示例：快速识别 / 阅读数据 / 感受变化 / 等待揭示。

**视觉证据**：这一段有什么只属于它的图形/空间/动作事实？
- 不能只是换标签；例如 V3 是“多股线合拢成核”，不是“网格 + V3 字”；
- 数据段必须有一个主差异先被看见，其他数据作为证据；
- 结尾要有只属于结尾的视觉结果，而不是“暗场 + 一行字”。

**镜头设计四问**：

1. **景别**：整体 / 中景 / 细节 / 极特写？主体占画面多大？为什么此刻从整体切到细节，或反过来？
2. **视点/机位**：正面 / 斜俯 / 俯视 / 沿轴推进 / 进入空间内部？观众从哪个位置看？同一根线在不同视点下是不同空间。
3. **空间层次**：前景 / 中景 / 背景至少两层有视差、尺度或焦点差异？还是全部贴在同一平面？
4. **运动目的**：揭示 / 强调规模 / 跟随事件 / 制造冲击 / 留白？固定机位也可以，但必须说明观看理由。

**镜头衔接**：为什么从上一段切到这一段？

- 形状匹配 / 动作接续 / 视线转移 / 尺度突变 / 光位变化 / 声音触发；
- 不能只是“上一段动画结束，下一段动画开始”；
- 下一段继承什么、重置什么。

**执行顺序**：整体 → 场景 → 镜头 → 帧。
先决定观众这一刻该看到什么、为什么看，再决定景别/视点/层次/衔接，最后才写帧级参数。不要让最容易实现的图形反过来决定内容。

- **BPM 网格只决定切点可以落在哪里，不决定每段等长**；时长由视觉权重 + 阅读任务 + 叙事重要性决定。
- 开场钩子、数据高潮、结尾收束必须显式标权重；不要 12 段全 2 秒。
- 数据/信息场景按“读完需要多久”定停留；不是固定 4–6 秒，也不是固定 2 秒。
- 场景类型、视觉权重、时长必须互相关联；只填类型不填时间分配，等于没设计。
- 每个关键属性先算：start/end frame、duration、easing、position/scale、visibility window。
- 能写成帧/参数/关系的，不靠看片判断；写不出的，说明还没设计。
- 镜头不是“大致这样动”，而是可以写成关键帧和曲线；但先有景别/视点/空间层次/衔接，再写曲线。

```ts
const shot = {
  from: 0,
  duration: 150,
  camera: [{ frame: 0, scale: 1.02 }, { frame: 150, scale: 1.08 }],
  focus: [{ frame: 0, target: 'grinder' }, { frame: 90, target: 'cup' }],
};
```

关键帧/时间/检查逻辑可直接用 `templates/visual-encoding.ts` 的 `Keyframe`、`at()`、`checkShot()`。

### 3.1 关键动作

不是每个镜头都要三阶段动画；但关键动作不能只写“磨豆/注水/拉花”，要写清怎么动。

| 动作 | 起始 → 中间 → 结束 | 路径/速度/停顿 | 镜头为什么动 | 光/材质如何响应 | 可见变化（画面证据） | 下一镜继承什么 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |

每个关键动作回答：

- 观众先看到什么变化？
- 运动路径是什么？匀速/加速/减速？哪里停？
- 相机为什么动、跟谁、何时停？
- 光/阴影/液体/粒子/材质如何对这个动作作出反应？
- 哪 1–2 秒是最难的中间态？
- 动作阶段还要写清：预备 → 触发 → 接触 → 反应 → 停顿；哪一拍是视觉重点？
- **可见变化**不能写“注水/光渐变/液面上升”；要写观众具体看见什么，例如：水柱接触粉床 → 粉床塌陷变暗 → 液面上升 → 杯壁透射色变深。
- 如果写不出可见变化，这个动作还没有被设计；先别写代码。

### 3.2 镜头差异与转场

每镜只回答四问，不要求填表：

1. 这一镜的新信息是什么？
2. 与上一镜的明确差异是什么？构图/尺度/视角/前中后景/运动方式/信息布局，至少一项真正承担差异。
3. 贯穿机制在这一镜发生了什么变化？建立/放大/分裂/重组/受阻/释放/消失。
4. 为什么在这里切？下一镜继承什么、重置什么？

- 不要求每镜换景别/运镜；固定机位可以，但连续两镜观看体验一样就要重想。
- 镜头差异不是“加元素”，是空间/视角/构图/信息的变化。
- 可选：需要已有镜头运动语法时，从 `capabilities/index.json` 的 video-shotcraft 取 1–3 张卡 + demo 源码；只借结构，按当前视觉系统重写。

### 3.3 最难动作先试

- 选 1–3 个高风险动作（机械/液体/形变/碰撞/光移），先做 3–5 秒局部预览；
- 看中间态、速度、相机和交接是否成立，再扩展到全片；
- 如果动作机制不成立，先换机制/媒介，不要加装饰；
- 这不是审批门，是为了少返工。

### 3.4 镜头落地追踪（首版渲染后填）

| 场景 | 计划镜头（景别/视点/层次/衔接） | 实际实现（相机/尺寸/图层/转场） | 证据帧 | 叙事落地 | 镜头落地 | 运动落地 | 衔接落地 |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |  |

每项填 `已实现 / 部分 / 未实现 + 证据帧`：

- **叙事落地**：新事实/阶段变化是否真的从画面看出来，而不只是换字？
- **镜头落地**：计划里的景别/视点/空间层次是否真的出现？还是只是平面缩放？
- **运动落地**：关键变化是否有起始 → 中间 → 结束，而不只是对象出现？
- **衔接落地**：上一镜与下一镜是否有预定的形状/动作/视线/尺度/光位/声音联系？还是硬切？

没落地=设计没实现，不能因为代码跑通就算完成。

## 6. 可选：animatic / 粗剪

多镜头可以先做低成本 animatic 验证节奏和切点，但它是工具，不需要 review JSON 或通过状态。

- 看什么：时间线是否成立、事件是否有因果、切点是否有理由、结尾是否收束；
- 如果 animatic 像幻灯片，先改镜头组织/关键画面，不要急着加材质；
- animatic 能说明节奏后再做精细画面；不需要审批门。

## 7. 自检

1. 去掉字幕，视觉弧还成立吗？
2. 核心视觉事件一眼能读出来吗？
3. 每个镜头是否让观众“换看什么”，还是只是换了物体？
4. 有没有视觉高潮/值得记住的一帧？
5. 切点有理由吗，还是每段结束就换图？
6. 结尾是动作完成，还是对象停住？
7. 这份 plan 是在帮助画面，还是已经变成填表？
