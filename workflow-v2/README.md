# 段级流程 v2 · 使用说明（给 AI 看的）

> 这是**第二套工作流**，与 `AIremotion-skill/01-流程与检查/02-流程/工作流-四段式.md` 并存。
> 四段式管**一镜之内**怎么做；这一套管**一段之内、镜与镜之间**怎么排、怎么验、怎么交。
> 顺序：**段 → 镜（四段式）→ 段验收 → 整片锁画**。

---

## 0. 门 0：开工检查（硬规则）

**没填完 `00-开工检查.md` 并贴出来，不许写代码、不许采集素材、不许出图。**

四项缺一不可：

1. **稿本 + 时长**：哪份稿、共几句、总时长、帧率（写文件路径）；
2. **DESIGN 候选**：2–3 张真实外观候选；**新片必须新建，不许沿用别的片**；
3. **大段表**：每段任务句 + 节奏三点 + 句/镜范围（覆盖校验必须通过）；
4. **素材需求清单**：每段要什么、类型、有没有；**只列需求，不许先抓**。

> 为什么是"门"：没有门时，AI 会先攒素材、再反推画面。
> 案例：`案例/2026-10-城市之夜.md`（只作参照，不是规则）。

---

## 0.5 门 0.5：创意定标（比 DESIGN 更早）

填 `00-创意定标.md`，六件事：

1. **野心档位**：A 静态图文 / B 动态图文 / C 电影感 / D 混合——由用户选，**AI 不许默认选最低**；
2. **先看再想**：打开 8–12 个 demo 源码（不是只看卡名），写"偷什么"，具体到数字；
3. **反面清单**：这条片子绝不能像什么（PPT / 贴纸 / 海报），写 3 条；
4. **记忆点**：每段至少一个"观众会记住的那一下"；
5. **运动合同**：AI 提 2–3 组参数（克制/中/强），用户选一组；写进 00-创意定标 第 2 节，后面 QA 对照它查；
6. **资源路线**：卡库 / 组件库 / 参考实拍 / 自研，四选一；选自研必须举 2 张"看过但不适用"的卡。

> **工作流是地板，不是天花板。**
> 检查（QA）只在最后兜底，用来防回归；创意必须在这一步先立起来。
> 没有这一条，AI 会踩着最低界限做（案例：`案例/2026-10-城市之夜.md`）。

怎么找卡、怎么读 demo：`方法/用卡库.md`（方法，不是题材清单）。
怎么把片子拔高：`方法/创作手段.md`（情绪板 / Beat 拆解 / 一段三概念 / Animatic / 限制驱动 / 声音先行 / A/B / Art Director / 失败博物馆）——**每片挑 3–5 个用，不是全上**。

## 1. 顺序禁令（违反即停）

| 禁止 | 为什么 |
|---|---|
| DESIGN 未确认就出图 | 风格会变成每镜各凭手感 |
| 段表未完成就写剧本 | 剧本会按句写，不是按段写 |
| 素材需求清单未完成就批量采集 | 会变成"素材先行"，拿画面凑文案 |
| 剧本未审就进制作 | 返工成本最高的位置 |
| 测试期间修改本流程 | 改前/改后混在一起，结果无法归因 |
| 证据放 `/tmp` | 会被清掉，复盘时无法回看 |

## 2. 流程（门 0 + 10 步 + 3 个门）

```
门 0  开工检查（稿本 / DESIGN 候选 / 段表 / 素材需求）
        ↓
门 0.5 创意定标（野心档位 / 看 8–12 卡 / 反面清单 / 记忆点 / 运动合同）
        ↓
① 定稿 + 配音          时基唯一
        ↓
② DESIGN.md            静态候选 → 动态测试 → 落参数        【门 1：风格定稿】
        ↓
③ 划段                 任务句 + 节奏三点 + 风险 + 句/镜范围
        ↓
④ 段剧本               7 字段（含取材），一段一份          【门 2：剧本确认】
        ↓
⑤ 关键状态             每段 3–5 条，存 shots/S<N>-证据/
        ↓
⑥ 制作                 段内逐镜走四段式；先完整预览再精修
        ↓
⑦ 段内验收             1× 看完 + 确定性 5 条 + 三测 + 技术自检
        ↓
⑧ 接入                 首尾接点 / 时基 / 素材版本
        ↓
⑨ 锁画                 全片 1× 审片，重点看段间接缝        【门 3：锁画】
        ↓
⑩ 交付 + 复盘          实际文件 1× 审看审听；返工原话 → 规则
```

## 3. 新片从 0 开始

```bash
cd ~/remotion/electron/workflow-v2
mkdir -p 片/<片名>
cp 00-创意定标.md          片/<片名>/00-创意定标.md
cp templates/DESIGN.md    片/<片名>/DESIGN.md
cp templates/大段表.md     片/<片名>/01-大段表.md
cp templates/镜头剧本.md   片/<片名>/02-镜头剧本.md
cp templates/关键状态.md   片/<片名>/03-关键状态.md
cp templates/任务书.md     片/<片名>/04-任务书.md
cp templates/QA.md        片/<片名>/05-QA.md
cp templates/复盘.md       片/<片名>/06-复盘.md
```

`实例-Token/` 只作参照，**不许直接复制内容**。

### 3.1 新片的工程怎么放（必须二选一，写在门 0 里）

| 模式 | 做法 | 适用 |
|---|---|---|
| **A 新工程**（推荐） | 新建独立 Remotion 工程目录，composition id 另起（如 `<片名>Film`） | 与已有片无关的新片 |
| **B 同工程新合成** | 新建 `timeline-<片名>.ts` + `<片名>Film.tsx`，注册新 composition | 复用素材/组件，但**不许改** Token 的 `timeline.ts` / `script-v4.json` / `TokenFilm.tsx` |

无论哪种，**`--map` 都要为新片重做一份**（镜号→稿号），不许沿用 Token 的。

## 4. 角色

| 角色 | 谁 | 职责 | 不许做 |
|---|---|---|---|
| 总控 | 主对话 | 门 0、DESIGN、划段、剧本、接共享件、锁画、复盘 | 把整段丢给子智能体就不管 |
| 段执行 | 子智能体 | 只做指定段：视觉设计 → 制作 → 段内自检 → 接入说明 | 改 timeline / 稿本 / 总合成 / 其它段 |
| 用户 | 你 | 三个门拍板；给返工原话 | —— |

## 6. 命令

```bash
cd ~/remotion/electron
npm run studio                 # 预览
npm run render                 # 成片
npx tsc --noEmit               # 类型检查

# 检索（一条命令，替代手工 grep）
python3 ~/AIremotion-skill/03-工具/search-craft.py --shot <N> --map 实例-Token/shot-script-map.json
python3 ~/AIremotion-skill/03-工具/search-craft.py 数字滚动 对比 --only cards   # 卡库按"手法"搜

# 门 0.5 门禁：资源路线 / 看过什么 / 自研举证
python3 ~/AIremotion-skill/03-工具/check-gate.py --film workflow-v2/片/<片名> --stage look

# 取材门禁（动手前跑一次，写完再跑一次）
python3 ~/AIremotion-skill/03-工具/check-shot.py --provenance remotion/shots/S<N>*.tsx
python3 ~/AIremotion-skill/03-工具/check-gate.py --film workflow-v2/片/<片名> \
  --stage shots --shots remotion/<片>/shots
```

> `search-craft.py` 默认只出**强命中**：自动提词要 ≥2 个词命中，你亲手给的关键词单个也算；`--weak` 才看弱命中。
> **`--shot` 必须配 `--map`**：镜号→稿号的映射表放在片目录里，换片/改时间轴必须重做。
> `check-shot.py --provenance` 会验：取材行存在、路径存在、**必须写「（抄：参数…）」**，
> 参数没进代码只告警、不拦（命名可能不同）。

## 7. 判定规则

- 段任务没达成 → 不许进下一段；
- 画面没有增量（只是把配音换成大字）→ 回剧本，不回实现；
- 同一处改到第 3 版还不行 → 换设计，不许调参数；
- 没 1× 看完 → 只能写"未验证"；
- 预览与最终工程两套代码 → 判失败。

## 8. 测试记录

每轮从 0 测试，新建 `RUN-<日期>.md`，只记四件事：

1. 这轮改了什么（版本/提交号）；
2. 卡在哪一步（第几步、哪条门）；
3. 暴露了什么问题（一句话，可判定）；
4. 下轮改什么。

> **测试期间冻结流程**：开跑后不再改 `workflow-v2/`、kit、工具。要改，先停跑、记版本、改完重跑。
