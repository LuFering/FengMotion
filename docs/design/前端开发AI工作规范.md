# 前端开发 AI 工作规范

> 同时阅读 [设计原则与已确认界面](前端设计原则与已确认界面.md) 和 [开发者协作规范](../dev/前端开发者协作规范.md)。任务明确指令优先。

## 开始前

1. 确认仓库、目标分支、提交和工作区；不将未合并分支当 main，不覆盖用户已有改动。
2. 阅读目标组件、样式、数据来源及邻近已确认界面。按实际主题与 CSS 引入顺序核对 token，不从互相矛盾的旧文档混搭。
3. 找到本功能的用户任务、第一眼、主要动作和目标对象。列出默认、有内容、执行中、空、错误或不可用的相关状态，以及何时出现。
4. 功能信息可以同时存在，但不意味着所有区域默认常驻。明确主次，避免将信息清单机械转为卡片清单。
5. 有冲突时先核对用户最新要求与适用范围；无法从现有信息合理决定且会影响关键方向时，列出证据再询问。

## 设计与实现

- 在现有页面上下文中先做主状态与关键交互，参考具体已确认截图、组件及其适用范围；不只模仿颜色和圆角。
- 新增 UI 应自然嵌入原界面，保留未要求改动的区域；优先复用适用的现有组件、样式与状态，不新增平行体系。
- 工作台画面优先；任务、问题、参考、交付按用户当前需要出现，不用大面积状态卡挤掉画面。空白不需要靠解释文案填满。
- 文案写用户当前状态和动作，删除重复标题、内部编号、假精确和“这里用于……”等教学式文案。保留影响决定的演示、错误和不可用提示。
- 不伪造 Agent 推理、工具调用、渲染、用户确认、版本或对比。演示与真实能力明确区分，工作流内容不从占位视频切片编造。
- 画面引用和修改范围与实际请求同源，项目、版本、时间及目标一致；后端未接入时如实标明。
- 补齐键盘、focus、hover、disabled、长文本、不同窗口及相关主题；不要仅用颜色表达状态。

## 核心路径

发指令前用户能看见目标和约束，选中不会自动提交；制作时画面与任务状态可同时存在，插话是生效、排队还是不支持必须真实反馈；完成后预览和修改目标应关联，缺少版本不伪造对比。

## 验收

1. 按仓库开发规范实际运行 `npm run build` 和 `npm run lint`，必要时 `npx tsc -b`；只报告实际结果。
2. 在目标分支运行页面，截取同视口、主题、数据和状态的完整前后图，并覆盖关键交互、空态、长文本和窄窗口；适用时覆盖其他主题。1440×900 可作桌面参考，不是唯一标准。
3. 实际看图，检查第一视觉焦点、画面比例、对齐、文字层级、重复文案、边框/标签密度、溢出及邻近区域回归；修正并重截。
4. 实际操作核心交互和键盘路径，检查错误及禁用态。不能运行或截图时明确写未验证，不以代码推断冒充视觉实测。
5. 交付说明改了什么、截图和复现步骤、真实/演示边界、构建和未验证范围。截图要真实可访问；构建通过不等于视觉达标。

禁止把候选界面擅自标为已确认；禁止为一个功能顺带改动其他已确认界面。
