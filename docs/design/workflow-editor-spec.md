# 工作流编辑器规范（workflow-editor-spec）

> 工作流是 FengMotion 的核心能力：**修改工作流内容就能制作不同类型的视频**。
> 本规范覆盖：概念模型 → 列表页 → 编辑器布局 → 节点类型 → 交互规则 → 技术方案。

## 一、概念模型（先分清两件事）

| | 工作流定义 | 创作任务 |
|---|---|---|
| 是什么 | 可长期保存/复制/编辑/复用的制作方案 | 某次具体的视频制作 |
| 生命周期 | 长期演进，有版本 | 一次执行，有状态（进行/等待/完成） |
| 记录 | 节点、连线、配置、提示词、检索范围 | 所用**工作流版本**、输入、执行过程、产出 |
| 铁律 | 修改工作流**不得**悄悄改变已运行任务的定义 | 任务必须记录执行时的工作流版本快照 |

## 二、工作流列表页（先做这个，再做编辑器）

每条工作流卡片/行显示：

- 名称、描述、用途（适合做什么类型的视频）、版本号
- 节点数量、更新时间、最近执行状态（`status.ts` 五键）
- 来源标记：**内置模板** / **我的工作流**（复制自模板或从零创建）

功能：搜索、分类筛选、创建、复制、编辑、测试（试运行）。
演示模板（内置，标注为示例）：**科普视频**、**产品宣传**、**参考片复刻**。

## 三、编辑器布局（四区）

```
┌──────────────────────────────────────────────────┐
│ 顶栏：工作流名 · 版本 · 保存状态 · 试运行 · 返回列表 │
├────────┬──────────────────────────┬──────────────┤
│ 节点库  │        画布               │   节点检查器  │
│ 搜索    │  拖拽/连线/缩放/框选       │  （所选节点） │
│ 分类    │  节点显示状态与摘要        │              │
├────────┴──────────────────────────┴──────────────┤
│ 执行与调试：节点顺序 · 输入输出 · 日志 · 耗时 · 重试 │
└──────────────────────────────────────────────────┘
```

**设计原则**：节点卡片只负责让用户看懂流程；复杂配置放右侧检查器；
运行细节放底部执行面板。工作流再复杂，画布也保持清晰。

### 左侧 · 节点库

搜索 + 分类，可拖入画布。节点类型（第一期）：

| 类型 | 作用 | 检查器配置 |
|---|---|---|
| 开始 / 结束 | 流程边界 | 输出/输入声明 |
| 输入 | 用户提供目标与约束 | 字段定义 |
| LLM | 模型调用 | 提示词、模型参数 |
| 参考片检索 | 找相似镜头/运镜/节奏 | 检索范围、过滤条件（风格/构图/运镜） |
| 特效检索 | 找可用技法与实现方法 | 检索范围、技法分类 |
| 素材选择 | 从「我的素材」取文件 | 类型/文件夹过滤 |
| 视频生成 | 生成镜头 | 参数、输出规格 |
| 质量检查 | 校验结果 | 检查项与阈值 |
| 条件分支 | 按条件走不同路径 | 条件表达式 |

### 中央 · 画布

节点增删、连线、重排、缩放、框选、复制、删除、撤销重做、自动布局、保存。
节点卡片显示：输入输出摘要、执行状态、错误摘要（不塞完整参数）。

### 右侧 · 节点检查器

按所选节点显示：提示词、检索范围、过滤条件、模型参数、特效选择规则、
输入输出 schema、重试策略。

### 底部 · 执行与调试

节点执行顺序、每节点输入输出、日志、耗时、失败原因、重试、
**从指定节点重新运行**；中间产物可预览。

## 四、交互规则

- 单节点测试：不跑全流程，单独喂输入测一个节点。
- 试运行与正式任务的区分：试运行结果不进入任务记录。
- 执行状态沿用 `status.ts`：running / waiting（等你选）/ failed / done / idle。
- 失败可重试；重试记录进执行面板日志。
- 保存前校验：孤立节点、缺失连线、必填配置缺失 → 明确列出。

## 五、技术方案（已核对）

- **画布库：`@xyflow/react` 12.x（React Flow）**
  - peer 依赖 `react >= 17`；本仓库 React 19.2 / Vite 8 / Tailwind v4 —— 兼容（npm 元数据已核对）。
  - 交互参考官方 AI Workflow Editor 模板 + Dify 执行调试 + Langflow Playground。
  - 视觉：**不使用其默认皮肤**，节点/连线按 `design-system.md` 重新做。
- 状态管理沿用现有 React 状态模式；不引入新的重型依赖。
- **不引入**向量数据库 / LLM 服务（未经确认）；后端未实现时用
  **明确标注的 mock adapter**（沿用现有「未接入」灰显模式），不得伪装成真实执行。

## 六、与知识库的调用链（阶段四）

```
创作目标 → 工作流执行 → 参考片检索（依据）→ 特效检索（方法）
→ 生成制作方案（结合参考证据、技法、素材、工作流约束）
→ 执行、检查与迭代（必要时重新检索或调整方案）
```

要求：检索结果**可追溯到来源片段或技法条目**（稳定 ID）；
任务记录检索证据与参数。检索到技法卡 ≠ 可自动执行 —— 只有卡片关联了
可执行代码/模板/工具/明确指令时，才允许显示「可执行」。

## 七、验收标准（阶段二）

- 工作流列表：建/复制/改/搜/筛选全部生效；模板标注为示例。
- 编辑器：拖拽、连线、配置、删除、撤销重做、自动布局、保存全部可用。
- 单节点测试与从指定节点重跑可用（mock 执行也必须真实反映状态流转）。
- `npx tsc -b` + `npm run build` 过；界面改动附真实截图。
