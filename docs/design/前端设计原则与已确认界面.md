## 产品与体验

FengMotion 是自然语言驱动的视频创作工作台：用户提出需求，查看 AI 的制作和画面，并引用场景、帧或区域提出修改。画面和具体操作优先，任务状态不应遮住当前画面。工作流默认 Prompt-first，不把可选 Gate 变为所有项目的强制审批；没有真实结构时不虚构镜头和时间，演示须如实标识。

素材、参考片、特效与工作流服务不同用户任务，共享基础控件但不强迫使用同一种页面模板。

## 设计原则

- 先明确用户第一眼看什么、主要操作是什么，再组织布局。视觉内容应突出。
- 同一信息有一个主要位置，不重复堆叠标题、状态、时间码和解释。
- 少解释界面：删除“点击这里查看”“这里会显示……”等无决策价值的常驻说明。未连接、演示、失败和不可用要真实、简短地告知。
- 用对齐、间距、字号和适度灰阶建立层级，避免卡片套卡片、标签云和每一段都加框。必要时可使用边框、圆角和阴影；去 AI 味不是一律取消所有层次。
- 不使用无目的渐变、发光、虚线装饰或炫技动画。保留可读性、键盘焦点和清晰操作反馈。
- 引用、定位、预览和版本对应真实项目与版本；无真实执行或对比数据时不伪造。对比画面应对应时间、尺寸与裁切。
- 桌面优先；窄屏不硬挤多栏。状态不只依赖颜色，覆盖 hover、focus、禁用和错误态。

## 规范来源与冲突

优先顺序：用户本次明确指令 → 对当前任务适用的已确认局部 → 本文及页面现行规格 → 运行中的相关组件和 CSS → 历史文档。代码是当前实现的事实，不自动代表用户已认可；更高优先级不意味着忽略不冲突的要求。

- 工作台核对 `src/views/Workbench.tsx`、`src/styles/workbench-a2.css` 的 `.wb-a2` 作用域与当前主题；当前工作台样式包含面板圆角和阴影，不能笼统套其他页面规则。
- 全局和主题核对 `src/index.css` 的引入顺序、`src/styles/brand.css` 及页面专用样式；同名变量可能被主题和作用域覆盖，实际计算值需要运行检查。
- `CLAUDE.md` 的珊瑚橙 `--brand`、旧灰阶及“P2 前不做时间轴/拖拽”，与后来代码和用户要求存在年代差异；不应据此重绘当前工作台。用户明确要求优先。
- `docs/design/design-system.md` 写蓝色 token，README 另写首页纸层与薄荷色工作台；可能涉及不同页面、主题或阶段。先核实适用范围，不擅自宣布某个数值是全站唯一真相。
- 原有组件复用要求仍有效。先查现有组件和状态语义，确认适用再复用；专用交互不硬套不匹配的通用外观。
