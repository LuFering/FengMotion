# 审核与测试清单

前端 PR 的审核与实测依据。由协作者（muse-lufering）执行与维护；清单随各期规格增补。结论用词遵循 [开发规范](开发规范.md) 第 5 节的验证状态词。

## A. 审核清单（看代码与 PR）

逐项过，任一阻塞项不满足则不通过：

| # | 检查项 | 级别 |
|---|---|---|
| A1 | 实现与施工规格逐项一致（结构、数值、状态、交互），无自行增删 | 阻塞 |
| A2 | 颜色/间距/圆角/字阶引用 token 或语义变量，无新造平行样式体系 | 阻塞 |
| A3 | 改动范围 = PR 声明范围，无顺手改动的无关文件与业务逻辑 | 阻塞 |
| A4 | 未接通能力显式标 Demo，无模拟冒充真实（按钮、状态、文案） | 阻塞 |
| A5 | 未保存/未执行/无数据等状态有明确表达，不默认成成功 | 建议→阻塞（视场景） |
| A6 | 新增文案、命名与既有术语一致（场景、产物、任务等） | 建议 |
| A7 | PR 按模板填写：变更说明、验证情况、未验证范围 | 阻塞 |

## B. 实测清单（拉分支到协作者环境实跑）

### B1 构建三件套（每个 PR 必跑）

- [ ] `npm install`（依赖有变化时）
- [ ] `npm run build`（含 tsc -b）通过
- [ ] `npm run lint` 通过（新增告警需在结论中列明）

### B2 视觉对照（涉及样式/布局的 PR）

- [ ] 涉及页面截图，与规格的基准逐项对照：页头、工具栏、卡片网格、抽屉
- [ ] 三主题各看一遍：深色 / 浅色 / 触感，无串色、无未覆盖的本地 token 残留
- [ ] 1440 宽与窄窗各看一遍：无溢出、无遮挡
- [ ] 控制台无新增报错

### B3 核心交互回归（按改动范围勾选）

- [ ] 导航六页可达且壳一致（顶栏/侧栏无重复、无残留死 DOM 影响）
- [ ] 三库页两次点击路径：特效（搜→点卡、点分类→点卡、点卡→复制配方）、参考片（点分类→点卡、点卡→点镜头段三处同步）、素材（搜→点文件、导入全流程、加入创作）
- [ ] 工作台四状态：正常创作 / Structured 等待 Gate / 执行失败 / 检查有问题——默认页签、Gate 卡位置、底部面板收起行为与规格一致
- [ ] iframe 三页：无重复导航、滚动正常、Demo 标识可见
- [ ] 加载 / 空数据 / 搜索无结果 / 错误四态：涉及页面逐个触发核对

### B4 结论格式

审核结论发在 PR 评论，固定结构：

```
结论：通过 / 有条件通过（建议项） / 不通过（阻塞项）
实测：构建 <状态词>、lint <状态词>、截图对照 <范围>、交互回归 <范围>
阻塞项：<条目 + 定位>
建议项：<条目>
未覆盖：<未测范围与原因>
```

## C. Bug 单格式（实测发现问题时）

现象 / 复现步骤 / 期望与实际 / 严重程度（阻塞、明显、轻微）/ 归属（提交方修复；一行级小修协作者可直接在 PR 分支修并注明）。
