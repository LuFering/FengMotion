# 前端开发者协作规范

> 面向维护者、前端开发者和使用 AI 的协作者。配套：[设计原则与已确认界面](../design/前端设计原则与已确认界面.md)、[AI 工作规范](../design/前端开发AI工作规范.md)。分支、PR 与检查遵循 [开发规范](开发规范.md)。

## 从用户任务开始

回答：谁在什么情况下做什么？第一眼应看到什么？主要动作是什么？新功能放哪里？哪些现有内容需要保留？哪些能力仍是演示？

功能需求与布局分开描述。“需要任务、问题、参考、交付”不等于四块同时常驻。写清默认状态、触发条件、关闭方式和与画面的关系。例如：制作中继续显示上一版预览，顶部显示正在生成新版；问题默认收起。

## 先验证主场景

选择一个代表性项目和主状态，说明数据真实或演示。先在完整页面里看布局和主要交互，再扩展空态、失败、长文本、窄屏和主题。存在重大视觉方向分歧时，先提供具体可审阅的截图。截图只证明对应版本、视口、主题、数据和状态；明确认可后记录截图或复现入口、提交和确认范围。

## 给 AI 下达任务

提供用户场景、位置和范围、主状态、其他状态、已认可的具体参考、禁止改动的部分、真实/演示边界和验收证据。不要只写“高级、现代、去 AI 味”。

### 可复制模板

```text
请为 FengMotion 开发【功能】，目标分支【分支】。
用户正在【场景】，希望【动作】；第一眼应看到【主体】。
功能放在【位置】，通过【动作】打开；默认显示【内容】，
执行中显示【状态】，无数据或失败时显示【状态】。
参考【页面/组件/截图】的【具体布局、密度或交互】；
保留【不能改的部分】，不要套用【不适用的组件】。
不要展示【重复信息或无用解释】；不得伪造数据和执行。
先做【主状态和关键交互】，再覆盖必要状态。
运行页面，提供相同视口、主题和数据的完整前后截图；
说明数据来源、真实/演示能力、检查结果和未验证范围。
```

## 反馈方法

指出具体位置、问题、期望和保留项，例如：“中间画面不够突出；交付和问题占太多位置。请让画面成为主体、问题默认收起，左侧待决定保持不变，给我完整前后截图。”

如果说不清问题，要求 AI 先运行截图，分析第一视觉焦点、空间比例、重复文字、边框密度和主要动作，再提出具体修改。开发者负责转译成 CSS 与交互；用户不必提供像素值。

## 审阅

- 产品：用户能否完成任务，主要内容、操作和出现时机是否清楚。
- 视觉：完整页面的主次、密度、对齐、可读性、邻近组件协调性；是否重复说明、边框和状态。
- 行为：点击、键盘、作用范围、引用、加载、失败和窄屏是否按真实数据工作。
- 真实性：模拟执行与不可用状态明确；文件、预览、版本和时间对应同一项目。
- 工程：复用适用组件和主题 token，控制修改范围，按开发规范执行构建和 lint。
- 证据：截图、命令结果与复现环境真实；未运行或未看到的状态标明未验证。

## 持续维护

规范冲突先对照适用页面、真实代码和用户最新决定，不确定就列待确认。新设计明确认可后更新清单，旧规范标历史或范围，不以个别新界面重绘所有页面。功能完成和视觉认可分别记录。
