# 前后端协议

本协议约定前端与（未来）Agent 后端之间的数据与状态契约。由协作者出前端稿、维护者确认后端可实现性与字段口径后冻结；冻结后的变更走第 6 节流程。

状态：v0.2（2026-10-23）。后端骨架按本协议开工（Spring Boot，`server/`）；在真实 Agent 接入前，服务端返回一律带 `demo: true`，前端仍可用演示适配器。

## 1. 总原则

- **唯一数据入口**：前端视图只经 `src/services/` 的 studioApi 层取数与执行动作，禁止视图内散落请求与数据拼装。
- **适配器可替换**：演示适配器与真实后端实现同一接口；切换实现不改视图代码。
- **契约先行**：新能力先在本文件补契约（字段、状态、错误），再写实现。
- **诚实标注**：凡经演示适配器返回的数据，UI 必须显式标注 Demo（见第 4 节）；禁止以演示结果冒充真实执行。

## 2. 通用约定

- ID：所有实体使用稳定字符串 ID；跨实体引用只用 ID，不嵌套整对象。
- 时间：统一毫秒时间戳（`startedAt` 等）或 ISO 8601 字符串，同一契约内不混用；时长用毫秒（`timecodeMs`、时长字段）并在字段名注明单位。
- 状态枚举：小写蛇形（`not_run`、`running`、`completed`、`failed`、`cancelled` …），枚举值只增不改义；废弃值保留并标注，不复用。
- 可空性：字段缺失用「不返回该字段」表达，不用空字符串或 0 冒充；未知状态必须有明确的未执行/无数据表达，不得默认成成功。

## 3. 核心对象（前端所需口径）

- **Project / Task**：项目与创作任务。任务状态是全站执行状态的唯一驱动源（工作台顶部摘要、任务页签、我的创作卡片状态都读同一状态，不各存一份）。
- **Artifact（产物）**：版本化产物（渲染结果、关键帧、方案等），带版本号与来源任务；产物浏览器当前为只读演示。
- **AgentReference**：Agent 对场景/帧/时间范围/区域/产物的结构化引用，分 target 与 context 两种角色（已在 studioApi 落地）。

## 4. Demo 标注规范

- 演示适配器返回的数据对象须带可识别的 demo 标记（现有 fixture 约定 `demo: true`）。
- UI 呈现：演示数据在页面上有可见的「演示」标识；由演示数据驱动的操作（恢复、检查通过等）必须禁用或明确标注为演示行为。
- 汇报与文档同样适用：演示链路跑通只能表述为「交互连通」，不得表述为「真实能力完成」。

## 5. 两份待冻结契约（01 期内冻结）

### 5.1 工作流契约

- `WorkflowDefinition`：工作流定义——节点、连线、参数、元信息、版本。
- `WorkflowRun`：运行实例——`runId`、`taskId`、状态（运行中/成功/失败/取消）、各节点输入输出与错误信息。
- 约定：原生页面与（过渡期）iframe 不得各存一份状态；运行状态与任务区保持一致，以 runId/taskId 关联追踪。

### 5.2 检查契约

- `CheckRun`：`checkRunId`、`taskId`、`renderId`、`status`（running/completed/failed/cancelled）、`startedAt`、`completedAt`；（后续）`supersedesCheckRunId` 关联被替代的旧检查。
- `CheckFinding`：`findingId`、`checkRunId`、`category`、`severity`、`title`、`description`、`targetType`（scene/timeline/render/asset/workflow_node）、`targetId`、`timecodeMs`（适用时）、`evidence`、`status`（未处理/处理中/已解决/已忽略）、`suggestedFix` 或 `fixAction`、时间戳。
- 语义红线：**未执行 ≠ 通过**；用户标记「已处理」≠ 复检通过——处理状态与检查结论是两个字段、两种表达。技术检查与内容/叙事检查分开呈现；叙事类结论必须有渲染预览或关键帧证据，不接受仅凭源码推断。

### 5.3 归属与边界

三层各只有一个归属：**域模型**（5.1 / 5.2 的类型与 `docs/契约-工作流.md`、`docs/契约-检查.md`）由 01 期 Issue 6 落地；**服务传输**（`src/services/studioApi.ts` 的类型与本文件第 3 节）由 studioApi 契约 PR 负责；**Agent 编排与任务协议**本期只记录、不冻结。同一字段只在一处定义，文档不复述字段。详见 [决策记录](决策记录/2026-10-23-契约边界.md)。

## 6. 契约变更流程

1. 提出方在本文件以 PR 形式修改契约，并写明变更原因与影响面。
2. 另一方确认可实现性（后端）或可呈现性（前端）后合并，视为新版冻结。
3. 已冻结字段不直接改义：需要新语义时新增字段或枚举值，旧值标注废弃并给出迁移期。
4. 实现跟不上契约时，先改演示适配器顶住并保持 Demo 标注，不私自改契约迁就实现。

## 7. 服务传输（HTTP + SSE）

后端实现本协议时使用固定传输口径，前端适配器按此实现 `HttpStudioApi`。后端工程独立于本仓库，位于同级目录 `FengMotion-backend/`（Spring Boot 3 / Java 21），本文件仍是契约的唯一事实来源。

- **基址**：`/api`；请求与响应均为 JSON，字段名与 `src/services/studioApi.ts` 一致（camelCase）。
- **时间**：响应统一 ISO 8601（UTC，带 `Z`）；不使用本地化时间字符串。
- **错误**：非 2xx 返回 `{ "code": string, "message": string }`。`404` 未知 id；`409` 非法状态迁移；`400` 参数不合法。
- **认证**：本机回环开发阶段不启用；接入远程前在此节补充。

### 7.1 端点

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/tasks` | `TaskRequest` | `AgentTask` |
| GET | `/api/tasks/{taskId}` | — | `AgentTask` |
| GET | `/api/tasks/{taskId}/events` | — | SSE，`event: task`，`data: TaskEvent` |
| POST | `/api/tasks/{taskId}/cancel` | — | `202`，无 body |
| GET | `/api/changes/{taskId}` | — | `ChangeSet`，无变更时 `404` |
| GET | `/api/versions` | — | `ProjectVersion[]` |
| POST | `/api/versions/{versionId}/restore` | — | `{ restored, message }` |
| POST | `/api/render` | `TaskRequest`（`kind=render`） | `AgentTask` |
| GET | `/api/health` | — | `{ status, demo }` |

### 7.2 SSE 约定

- 每条事件一帧：`event: task` + `data: <TaskEvent JSON>`；连接建立先发当前状态的一帧。
- 每 15s 发送心跳注释帧 `: ping`，避免中间层断流。
- 任务进入终态（`completed` / `failed` / `cancelled`）后，服务端发完该帧即关闭流；客户端重连需带 `Last-Event-ID`（本阶段可不实现回放，重连从当前状态重发）。

### 7.3 状态机

`queued → running → building → completed`，任一阶段可 `cancelled`；失败走 `failed`。迁移必须由服务端唯一裁决，客户端只能发起 `cancel`，不能改状态。

### 7.4 Demo 边界

真实 Agent、Remotion 渲染、文件写入均未接入。本阶段服务端只推进可见状态并返回 `demo: true`，不得表述为「真实执行完成」；`restore` 一律返回 `restored: false` 并说明原因。
