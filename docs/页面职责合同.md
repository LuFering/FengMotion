# FengMotion 页面职责合同

> 版本：v1 · 2026-10-15
> 适用范围：除「首页」「制作工作台」之外的全部页面（这两个已获正面反馈，本轮不动）。
> 性质：这是**产品合同**，不是 UI 设计稿。界面改造必须等这份合同确认后再开始。
> 已确认的三条决策：
> 1. 先立职责与状态模型，不动界面。
> 2. 音频与时间、素材库**保留独立入口**，但重新定位（时序校验中心 / 创作资产中心）。
> 3. 未接入能力（解析 / ASR / 云渲染 / 落盘）**按目标形态画出来**，不可用的动作置灰并写明原因。

---

## 零、一句话定位

> 以制作工作台为执行中心，以项目为上下文，以可复用的创作技法为工具，以质量判据为约束，
> 并从用户的修改反馈中持续积累经验的 AI 视频创作系统。

判断一个页面该不该存在的唯一标准：**用户能不能在这里完成一个任务并知道下一步。**
解释不出独立价值的页面，合并或取消。

## 一、统一状态模型（所有页面共用）

这是当前最缺的一层。界面上出现的"规格冒充已解析""点了停用没反应""移除卡后计数不变"，
根因都是把下面这些状态压成了一个 `ready`。

### 1.1 资源状态模型（五个维度正交，不是一个字段）

> 修订说明（v1.1）：v1 把"已确认/已应用/已停用"压成一条互斥的生命周期链，这是错的——
> 一项技法被三个项目引用，它仍处在"已确认可用"。**处理进度、审核、可用性、引用关系、来源**
> 是五个独立维度，界面上的状态标签由它们组合而成。

| 维度 | 回答什么 | 取值 |
|---|---|---|
| **来源类型** | 从哪来 | 内置资源 / 用户导入 / 示例数据 |
| **处理状态** | 处理到哪一步 | 待解析 / 解析中 / 解析完成 / 解析失败 |
| **审核状态** | 人确认过吗 | 未产生 / 待审核 / 已通过 / 已驳回 |
| **可用状态** | 现在还能用吗 | 启用 / 停用 / 弃用 |
| **引用关系** | 被谁用了 | 项目 / 制作单元的引用列表（多值，不是状态） |

示例组合：
- 内置技法：来源=内置资源 · 审核=已通过 · 可用=启用 · 引用=3 个制作单元
- 新上传视频：来源=用户导入 · 处理=待解析 · 审核=未产生 · 可用=启用 · 引用=无
- 已停用技法：审核=已通过 · 可用=停用 · 引用=保留历史引用（不允许新的应用操作）

**转换规则（合法）**
```
来源类型：导入即确定，不可变（内置资源永远不是用户导入）
处理状态：待解析 → 解析中 → 解析完成 | 解析失败
          解析失败 → 待解析（可重试）；解析完成 → 待解析（重新解析）
审核状态：解析完成 → 待审核 → 已通过 | 已驳回
          已驳回 → 待审核（修订后可再提）
可用状态：启用 ⇄ 停用；启用|停用 → 弃用（终端）
引用关系：任意时刻可增删；可用状态=停用 时禁止新增引用，但保留已有引用
```

**非法转换（界面必须阻止或置灰）**
- 未"解析完成"就进入"已通过"
- 可用状态=弃用 后回到启用
- 可用状态=停用 时新增引用
- 把"已应用"当作状态的终态（它是引用关系，不是状态）

**删除/停用时的连带规范**
1. 移除资源：先从所有引用中摘除（或阻止并列出引用方），再移除本体
2. 停用资源：保留引用与历史，禁止新增引用；下游列表默认隐藏，可切换"显示已停用"
3. 所有派生统计（列表计数、分类计数、来源计数、预览数）必须由同一份可见集合计算
4. 移除当前选中项后，选中下一个可见项；没有可见项时进入空态并清空详情
5. 界面任何写操作，若不会持久化，必须在**操作前**让用户知道（不只是角落一行提示）

### 1.2 交付物状态

```
未组装 ──► 组装中 ──► 可交付 ──► 已交付
   │                     │
   └─► 缺件（列出缺什么）  └─► 验收未通过（列出未通过的判据）
```

- 未组装时**不给下载按钮**，而是列出还缺哪些组装步骤/验证条件。
- 云渲染未接入时，展示真实已有的成片与可交付状态；渲染动作置灰并写"云渲染未接入"。

### 1.3 未接入能力的统一表达

| 能力 | 界面表达 | 动作状态 |
|---|---|---|
| 视频/技能包解析 | 新导入的资源停在「待解析」 | 「开始解析」置灰，旁注"解析未接入" |
| ASR | 口播只给估算值，不给判定 | 「识别对齐」置灰，旁注"ASR 未接入" |
| 云渲染 | 只展示真实已成片 | 「渲染」置灰，旁注"云渲染未接入" |
| 落盘 | 所有写操作标注「仅本次会话有效」 | 正常可用，但结果不承诺保留 |

**原则**：按目标形态画出来，把"为什么现在不能用"写成一句人话，而不是隐藏按钮或假装能用。

### 1.4 术语表（消灭内部黑话）

| 现在 | 统一为 | 说明 |
|---|---|---|
| 镜头卡 / 卡 | **创作技法** | 通用层不许出现范式词（镜头） |
| 镜头卡库 | **创作技法库** | 同上 |
| 视频库 | **参考片库** | 主体是真实参考视频 |
| 片型画像 / 规格 | **片型画像** | 与"参考片"是两种对象，不得混标状态 |
| 样片 | **预览动效** | |
| 判例 | **规则**（页面叫「反馈与规则」） | 一条原话 ≠ 一条通用规则 |
| V3 / 旧版 | **当前脚本 / 已成片** | 版本号是内部代号 |
| Unit / 单元 | **制作单元** | 通用层统一叫法 |
| 草稿时间轴 | **脚本时间轴** | 与"成片时间轴"相对 |
| 未落盘 / 内存里 | **仅本次会话有效** | |
| 后端未接入 | **解析未接入 / ASR 未接入 / 云渲染未接入** | 指名道姓，不要笼统说"后端" |

### 1.5 核心对象与边界（一个对象只承担一种意义）

| 对象 | 职责 | 不得混用的对象 |
|---|---|---|
| 项目 | 创作目标、阶段、产物、状态 | — |
| 制作单元 | 具体内容、执行结果、验收状态 | — |
| 创作资产 | 真实资源、元数据、使用关系 | — |
| 技法 | 可复用表现方式、参数、适用条件 | — |
| 参考案例 | 有来源、有证据的学习材料 | 不得与「片型画像」混标 |
| 片型画像 | 对某类作品的抽象描述（节奏/构成/出镜比例） | 不得冒充"已解析视频" |
| 反馈事件 | 用户在某次任务里说了什么、驳回了什么 | 不得直接当规则 |
| 规则候选 | 从反馈归纳出的待审核经验 | 不得直接生效 |
| 生效规则 | 审核通过、有适用范围、可参与执行 | 不得无适用范围 |
| 质量门槛 | 前置条件、验收标准、结果证据 | — |
| 交付物 | 版本、生成状态、可用文件 | — |

### 1.6 能力依赖四分类（不得把"界面能做出来"当成"功能已完成"）

| 类别 | 含义 | 界面要求 |
|---|---|---|
| **A 纯前端可实现** | 无需新数据、无需持久化 | 直接做，真实生效 |
| **B 现有真实数据可实现** | 数据在仓库里，只是没接进这个页面 | 直接做，数据必须是真的 |
| **C 需要持久化支持** | 交互能做，但结果存不下来 | 界面做出来，**操作前明确告知不会保存**（不是角落一行小字） |
| **D 需要新增后端能力** | 解析 / ASR / 云渲染等 | 按目标形态画出来，动作置灰并写明"XX 未接入" |

各页归类（随实现推进更新）：

| 页面 | 主要依赖 | 备注 |
|---|---|---|
| 项目指挥中心 | B（阶段、产物、任务活动数据已有） | 阻塞项判定属 A |
| 创作资产中心 | B（素材台账含来源/许可/使用位置） | 加入项目、适用性判定属 C |
| 内容编排中心 | B（分镜 73 段、成片 30 单元、7 处映射） | 编辑属 C；ASR 对齐属 D |
| 时序校验中心 | B（时间轴与映射数据已有） | 差异计算属 A |
| 发布与验收中心 | B（成片文件真实可下） | 云渲染属 D |
| 资源接入与解析中心 | A（导入与来源管理）+ D（解析） | 新导入一律停「待解析」 |
| 创作技法库 | B（157 张技法及详情） | 应用到制作单元属 C |
| 参考片库 | B（3 个实测画像）+ A（拆分片型画像） | 上传解析属 D |
| 反馈与规则中心 | B（27 条真实判例与用户原话） | **规则审核/启用/停用/命中追踪属 C**（原合同误标为"否"） |
| 流程与质量保障中心 | B（10 阶段 13 门槛） | 与项目状态联动属 A；门槛状态更新属 C |

## 二、十个页面的职责合同

每页六项：**目标用户 / 主要任务 / 核心对象 / 帮用户做什么决定 / 主要操作 / 完成后下一步**。

### 1. 项目总览 → 项目指挥中心

| 项 | 内容 |
|---|---|
| 目标用户 | 正在推进某个项目的创作者 |
| 主要任务 | 判断项目能否继续 / 找到下一步该做的事 / 进入制作 |
| 核心对象 | 项目、阶段、质量门槛、交付物、变更记录 |
| 帮用户决定的事 | **这个项目现在能不能往下走？不能的话卡在哪？** |
| 主要操作 | 看当前阶段与阻塞项、看未通过的门槛、看最近有效变更、点「继续制作」 |
| 完成后下一步 | 进入制作工作台；或进入造成阻塞的那个页面（内容编排 / 资产 / 时序校验 / 验收） |
| 与现状的差距 | 现在是静态状态展示（四件事），要改成**面向下一步行动**：阻塞项与「继续制作」是主角 |
| 依赖后端 | 否（阶段与产物数据已有） |

### 2. 素材库 → 创作资产中心（保留独立入口）

| 项 | 内容 |
|---|---|
| 目标用户 | 需要找资源、判断资源能不能用的人 |
| 主要任务 | 找到可用素材 / 判断它适不适合当前画面 / 知道它用在哪、还缺什么 |
| 核心对象 | 创作资产（真实文件、用途、质量、关联项目、关联制作单元、使用记录） |
| 帮用户决定的事 | **这份素材能不能用在我的这个画面上？我已经有哪些、还缺哪些？** |
| 主要操作 | 预览、按项目/用途筛选、加入项目、查看使用位置、标记缺失 |
| 完成后下一步 | 进入工作台对应制作单元使用；或进入内容编排补脚本 |
| 与现状的差距 | 现在是图片/字体/音频台账（Table+Tabs），要改成**围绕使用决策**；需补字段：用途、关联单元、使用记录、适用性判断 |
| 依赖后端 | 部分（适用性判断、缺失识别需能力；可先做"未分析"状态） |
| 硬规则 | 「尚未分析」与「已确认不适用」必须分开，不能用空字段代替判断 |

### 3. 脚本与口播 → 内容编排中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要把脚本发展成可制作内容的人 |
| 主要任务 | 编排段落 / 看版本差异 / 评估时长 / 校验口播 |
| 核心对象 | 脚本段落（表达什么、对应什么画面、旁白多长、与前后如何衔接、改了影响什么） |
| 帮用户决定的事 | **这段内容表达成立吗？脚本和画面对得上吗？改哪一段？** |
| 主要操作 | 编辑段落、看版本差异、看时长估算、定位受影响的下游内容 |
| 完成后下一步 | 进入工作台制作该段落；或进入时序校验看时间是否对得上 |
| 与现状的差距 | 现在是"两份脚本并排看"，要改成**可持续演进的段落结构**；术语 V3/旧版 → 当前脚本/已成片 |
| 依赖后端 | ASR（未接入时只给估算，不给判定，并标注） |

### 4. 音频与时间 → 时序校验中心（保留独立入口）

| 项 | 内容 |
|---|---|
| 目标用户 | 要对齐草稿、旁白、音频与成片的人 |
| 主要任务 | 找出时间上的不一致 / 定位到具体段落 / 进入工作台处理 |
| 核心对象 | 脚本时间轴、成片时间轴、两轴映射关系、时间偏差、未匹配段落 |
| 帮用户决定的事 | **哪里对不上？差多少？要不要改？** |
| 主要操作 | 看差异清单、点某条差异跳到对应内容、标记已处理 |
| 完成后下一步 | 进入工作台的对应制作单元调整 |
| 与现状的差距 | 现在只是"两根长短不同的轴并排"，要改成**差异驱动的校验清单**（差异是主角，轴是导航） |
| 依赖后端 | 否（映射与时间数据已有） |
| 硬规则 | 152s 成片 vs 253.2s 脚本时间轴不是错误，必须在界面上说清"这是两条不同的时间线" |

### 5. 渲染与交付 → 发布与验收中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要交付成果的人 |
| 主要任务 | 判断能否交付 / 看交付物完整性 / 处理未通过的验收项 / 导出 |
| 核心对象 | 交付物（版本、生成状态、可用文件）、质量门槛结果、缺失项 |
| 帮用户决定的事 | **现在能不能交付？不能的话缺什么？** |
| 主要操作 | 看验收结果、看缺件清单、下载真实可交付文件、发起渲染（未接入则置灰） |
| 完成后下一步 | 交付；或回到工作台/内容编排补齐缺失项 |
| 与现状的差距 | 现在以"渲染任务列表"为核心，要改成**验收与交付**为核心；未组装版本要列出缺什么，而不是给一个不可用的下载按钮 |
| 依赖后端 | 云渲染（未接入时置灰 + 说明） |

### 6. 知识源 → 资源接入与解析中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要把外部资源变成系统可识别内容的人 |
| 主要任务 | 导入来源 / 跟踪解析任务 / 审核解析产物 |
| 核心对象 | 来源、导入批次、解析任务、解析产物 |
| 帮用户决定的事 | **这批东西解析了吗？产物对不对？要不要留下？** |
| 主要操作 | 导入（文件/网址/技能包/参考视频）、查看解析任务状态、审核产物、归入哪个资源库、重新解析、移除 |
| 完成后下一步 | 进入创作技法库 / 参考片库使用这批产物 |
| 与现状的差距 | 现在只有"导入区 + 来源列表"两块，缺**解析任务**与**产物审核**两块；四种来源（文件/网址/技能包/参考视频）不共享同一种解析逻辑，不能压成一套状态 |
| 依赖后端 | 解析（未接入时停在「待解析」+ 置灰开始解析） |
| 硬规则 | 预置来源不得标"已解析"；对预置来源的写操作必须真正生效或明确置灰 |

### 7. 镜头卡库 → 创作技法库（改名，与分层约定对齐）

| 项 | 内容 |
|---|---|
| 目标用户 | 要找表现手法并用到当前创作的人 |
| 主要任务 | 找到技法 / 判断适不适合 / 用起来 |
| 核心对象 | 技法（解决什么表达问题、适用场景、需要什么输入、预期效果、限制） |
| 帮用户决定的事 | **这个技法解决我的问题吗？适不适合我现在的画面？接下来怎么用？** |
| 主要操作 | 搜索筛选、看效果、看适用判断、看参数与实现、试用、应用到项目/制作单元 |
| 完成后下一步 | 进入工作台的对应制作单元应用；或继续找可组合的技法 |
| 与现状的差距 | 现在只能筛选+看详情+停用/移除（资料浏览器），要改成**四层信息**：效果认知 → 适用判断 → 执行信息 → 实际应用；首屏必须回答"这是什么、适不适合我、接下来能做什么" |
| 依赖后端 | 部分（"应用到制作单元"需工作台联动，可先做"复制配方/标记待用"） |
| 硬规则 | 改名为「创作技法库」：通用层不得出现"镜头"这类范式词 |

### 8. 视频库 → 参考片与案例研究中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要从已有作品里学做法的人 |
| 主要任务 | 研究参考片 / 比较 / 提取可复用做法 / 关联到项目 |
| 核心对象 | 参考片（真实文件、时长、关键帧、分析记录、引用位置）、片型画像（抽象经验参数） |
| 帮用户决定的事 | **我能从这部片子里借鉴什么？用在哪？** |
| 主要操作 | 上传参考片、看抽取的做法、把做法关联到技法库/项目/制作单元 |
| 完成后下一步 | 进入创作技法库找对应技法；或进入工作台应用 |
| 与现状的差距 | 现在把 3 个实测画像和 3 个片型规格混成 6 条"已解析视频"——**必须在数据模型层拆开**：参考片有文件与抽帧，片型画像只有经验参数，两者可关联但不得同状态 |
| 依赖后端 | 解析（未接入时新上传的停在「待解析」） |

### 9. 判例 → 反馈与规则中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要让 AI 越做越对的人（创作者本人 / 项目负责人） |
| 主要任务 | 审核反馈 / 提炼规则 / 定适用范围 / 看规则是否真的起效 |
| 核心对象 | 反馈事件（用户说了什么、驳回了什么）、规则候选、生效规则 |
| 帮用户决定的事 | **这条经验该不该成为规则？适用于什么范围？它后来真的管用吗？** |
| 主要操作 | 看反馈来源与原话、审核候选规则、修订适用范围与例外、启用/停用、查看命中记录 |
| 完成后下一步 | 规则参与后续任务；或回到工作台重做被驳回的部分 |
| 与现状的差距 | 现在是"27 条规矩 + 原话"的只读清单，缺**反馈 → 候选 → 生效**三层与适用范围；一条原话 ≠ 一条无条件通用规则 |
| 依赖后端 | 否（数据已有，缺的是模型的三层拆分与审核动作） |

### 10. 方法与流程 → 制作流程与质量保障中心

| 项 | 内容 |
|---|---|
| 目标用户 | 要知道完成标准、并确认作品为什么能继续推进的人 |
| 主要任务 | 查某阶段的完成标准 / 看当前项目哪些门槛没过 / 补证据 |
| 核心对象 | 质量门槛（适用阶段、适用条件、验收标准、应提交的证据、当前状态、不通过的处理建议） |
| 帮用户决定的事 | **这个阶段算过吗？没过差什么证据？** |
| 主要操作 | 看门槛清单、看当前项目命中了哪些、跳到缺失证据所在页面、申请豁免（可选门槛） |
| 完成后下一步 | 进入对应页面补证据；或继续下一阶段 |
| 与现状的差距 | 现在是静态流程说明（10 阶段 13 门槛），要改成**可执行的验收规范**并与项目状态联动 |
| 依赖后端 | 否（门槛是静态规范；与项目联动需要项目侧状态，已有） |
| 硬规则 | 不要把所有项目塞进同样的 13 道门槛：必要门槛不可跳过，可选项不得制造无意义阻塞 |

## 三、导航重划（方案建议，待确认后执行）

一级分组代表**用户要处理的工作领域**，不是"系统里存了什么数据"。

```
首页
制作工作台
项目与交付            ← 处理当前正在制作的作品及其产出
  ├── 项目指挥中心
  ├── 内容编排
  ├── 创作资产
  ├── 时序校验
  └── 发布与验收
创作资源              ← 可以跨项目发现、调用、复用的资源
  ├── 资源接入
  ├── 创作技法库
  ├── 参考片库
  └── 创作资产（全局视图）
规则与质量            ← 系统如何验收、约束、改进创作行为
  ├── 反馈与规则
  └── 流程与质量保障
```

说明：
- 创作资产同时支持**全局入口**与**项目内入口**：进入方式不同、关注点不同，但底层是同一份资源，不是两套数据。
- 跨领域对象不必强行归入唯一位置（一项技法既是全局资源，也可被某个项目引用）。

## 四、验收标准（改完之后怎么判断成了）

| 维度 | 成功标准 |
|---|---|
| 页面定位 | 每页都有独立且清晰的主要任务；解释不出独立价值的页面已合并或取消 |
| 操作闭环 | 用户能完成主要任务，并知道结果与下一步，而不是只浏览 |
| 页面协作 | 技法、素材、脚本、规则、项目之间能建立实际关联与跳转 |
| 状态真实性 | 不存在按钮无效、状态假成功、统计口径冲突、规格冒充真实产物 |
| 信息组织 | 先给"作决定所需的信息"，再给详细参数/来源/技术信息 |
| 经验沉淀 | 反馈可追踪、可审核、可转化为规则，并在后续任务中复用 |
| 可扩展性 | 更换制作范式时，不需要重写通用层的项目管理、创作资产与质量治理 |
