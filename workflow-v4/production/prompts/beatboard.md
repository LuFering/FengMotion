# G2 · Beatboard

> 只做解法，不写秒数。每个 beat 是问题，不是分镜。

对 brief 的每个 beat：

1. 抄 `mustAchieve`；
2. 给 2 种视觉解法（建议；v1 最低 1 个），至少 1 种不在 `mayUse` 里；
3. 选 1 种，写 `whyChosen`；
4. 有备选时写 `rejected`：为什么不是另一个；v1 不强制；
5. 检查有没有踩 `avoid`。

## 好解法的标准

- 它解决的是 `mustAchieve`，不是“把 brief 的 visual 画出来”；
- 它和载体是同一个机制，不是另起一个场景；
- 它在没有字幕解释时也能成立；
- 它有一个可被镜头看见的变化，而不是靠音效/字幕说。

## 先杀默认

先列 3 个最省力的解法，然后否掉：

- 照片 + 推拉；
- 整屏大字卡；
- 居中标题 + 淡入；
- 纯光效/粒子，没有信息；
- 八个场景轮播。

如果最后选的还是其中一个，写清为什么它在这里是必要的，而不是省力。

## 输出

`production.json` 的 `beats[]`：

```json
{
  "order": 1,
  "mustAchieve": "...",
  "options": [
    { "name": "...", "how": "...", "why": "..." },
    { "name": "...", "how": "...", "why": "..." }
  ],
  "chosen": "...",
  "whyChosen": "...",
  "rejected": "..."
}
```
