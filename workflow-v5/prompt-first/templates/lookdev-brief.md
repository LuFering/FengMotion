## 6. 视觉系统 → 视觉编码（选定方向）

> 这一节不是形容词，是能直接写成 token/参数/规则的设计。能在代码里推理的，不要靠渲染后猜。

### 6.1 设计 token（代码常量）

| token | 值 | 用途 |
|---|---|---|
| color.bg |  | 背景/暗部 |
| color.surface |  | 台面/墙面 |
| color.subject |  | 主体/杯子/纸张 |
| color.accent |  | 窗光/强调/文字 |
| type.family |  | 字体类别 |
| type.scale |  | 标题/正文/字幕字号 |
| grid.columns / margin / gutter |  | 构图网格 |
| motion.fast / base / slow |  | 动作时长 |
| ease.enter / exit / move |  | 缓动曲线 |
| camera.height / focal / move |  | 机位与运动 |
| light.key / fill / falloff |  | 主光/补光/衰减 |

- token 是代码常量，镜头里不写死颜色、时长、字号。
- 每个 token 必须能写成具体值；写不出值，说明还没设计。

### 6.2 构图与层级规则

- 焦点层级：第一眼/第二眼/背景各是什么；
- 安全区：主体/文字/字幕不能压到哪里；
- 对比：明度/色相/冷暖/虚实如何分开主体；
- 留白：哪里必须空，为什么；
- 文字：字号、行宽、位置、与画面的关系。

### 6.3 视觉原语（组件）

- 优先用 Stage / Light / Subject / Camera / Liquid / Text 这类原语；
- 每个原语接受 token，不写死魔数；
- 没有经过验证的原语，先建一个，不要在镜头里堆 one-off 形状；
- 同一原语在不同镜头复用，保证材质/光/尺度一致。

### 6.4 可计算不变量

先在代码/参数里检查，再渲染：

- 主体是否始终在画面/安全区；
- 文字是否超出安全区或压到主体；
- 关键动作是否有可见窗口（start/end 帧）；
- 状态是否连续（液面/位置/颜色不跳变）；
- 时间边界是否在帧数内。

### 6.5 代码形状（示例）

```ts
const tokens = {
  color: { bg: '#17110d', subject: '#e8d6b8', accent: '#c99a62' },
  type: { family: 'Noto Serif CJK SC', scale: [72, 44, 28] },
  grid: { columns: 12, margin: 96, gutter: 24 },
  motion: { fast: 12, base: 24, slow: 48, ease: 'cubic-bezier(.22,.61,.36,1)' },
} as const;

const shot = {
  from: 0,
  duration: 150,
  camera: [{ frame: 0, scale: 1.02 }, { frame: 150, scale: 1.08 }],
  focus: [{ frame: 0, target: 'grinder' }, { frame: 90, target: 'cup' }],
};
```

可复制 `templates/visual-encoding.ts`：tokens / Keyframe / at() / checkShot() 的代码骨架。它不是门禁，是让设计先变成可计算结构。

## 9. 失败时先换什么

1. 视觉方向不对 → 换 art direction / 媒介；
2. 构图不对 → 改焦点/留白/层次；
3. 光不对 → 改方向/软硬/受光面；
4. 材质不对 → 加纹理/分层/素材，不堆渐变；
5. 镜头不对 → 改景别/机位/景深；
6. 运动不对 → 改动作/时间/曲线；
7. 文字不对 → 改字体/层级/位置。
