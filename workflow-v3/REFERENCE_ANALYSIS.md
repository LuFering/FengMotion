# 参考分析 · v3

> 排在场景规格之前。**没有参考，就先提出视觉方向；不要在抽象描述上直接写代码。**
> 参考不是拿来抄的，是拿来把“高级感”拆成可复现的构图、材质、运动和时间。

---

## 1. 输入

- 1–3 个参考：视频 / 图片 / 网站 / 已有片子；
- 视频必须标时间码，并抽 3–5 张关键帧；
- 每条参考写清：**喜欢什么、不喜欢什么、为什么**；
- 截图/抽帧存 `refs/<来源>-<时间码>.png`，不放 `/tmp`。

### 1.3 参考日志（机器可查）

在片目录写 `reference-log.json`：

```json
{
  "queries": [{"tool": "search-craft", "args": "--index"}],
  "cards": [{"name": "depth-layer-moves", "openedAt": "2026-10-18T17:00:00"}],

```

- `cards` 至少 3 条，`refs` 至少 1 条，`selected` 不能空；
- 每条都要有时间戳/路径，证明是**写代码前**看的；
- 每场的 `source` 要能对上这里的一条。

## 2. 分析表

| 维度 | 参考里看到什么 | 要不要复现 |
|---|---|---|
| 构图 | 主体位置、留白比例、地平线、焦点数 | 复现 / 适配 / 不复现 |
| 色彩 | 底色、主色、强调色、对比关系 | |
| 材质 | 纸、金属、玻璃、颗粒、手绘、实拍 | |
| 画面密度 | 每屏元素数量、信息层级 | |
| 镜头 | 固定 / 推拉 / 横移 / 手持 / 无镜头 | |
| 主体运动 | 生长、变形、位移、遮挡、粒子 | |
| 节奏 | 快慢、停顿、重复、加速点 | |
| 转场 | 硬切 / 遮罩 / 连续变形 / 同元素贯穿 | |

---

## 3. 三类结论（必须分开）

1. **可复现**：机制清楚、成本可控，直接写进组件合同；
2. **需适配**：风格对，但题材/画幅/节奏要改，写清改什么；
3. **不可复现**：依赖实拍、生成模型或高成本 3D，明确放弃，不许假装能做。

> “不可复现”不是失败，是边界。写出来，后面才不会偷偷降级成照片。

---

## 4. 两到三个视觉方向

每个方向写：

- 一句话：观众第一眼看到什么；
- 主视觉媒介：程序化图形 / SVG 资产 / 生成图片 / 实拍视频 / 3D；
- 运动机制：path / mask / procedural / layered / transform；
- 参考贴合度：哪些像、哪些不像；
- 成本与风险：实现难度、渲染成本、素材依赖；
- 推荐理由。

用户选定一个方向后，才允许冻结场景规格。

---

## 5. 关键画面确认（门）

在写组件之前，先出 **2–3 张关键画面**（可以是渲染帧、拼贴、风格板）：

- 同一句文案、同一画幅、同一字体/配色；
- 每张标：这一帧在片子里的时间点、要验证什么；
- 用户明确选一张，或说清“要哪张的什么、不要哪张的什么”。

**关键画面没确认 → 不许写组件。**
这不是把片子做成 PPT，而是先确认动画要围绕什么视觉主体展开。

---

## 6. 没有参考时

允许 AI 自主探索，但必须：

1. 先提 2–3 个具体方向（不是“高级感”“电影感”这类形容词）；
2. 每个方向说清主视觉媒介和运动机制；
3. 先出关键画面，再写代码；
4. 不许用“找不到参考”当借口直接回到图片轮播。
