# 迭代工作流 · v3

> 默认不是“重新生成整段”，而是**定位到最小单位，改一个参数/一个组件，再看一遍**。
> 迭代必须建立在真实渲染结果上，不是文档上的想象。

---

## 1. 先分类，再动手

| 问题 | 先改什么 | 不要做什么 |
|---|---|---|
| 构图不对 | scene spec 的 `layers` / 画幅 / 机位 | 重写组件 |
| 资产不对 | 换资产、调尺寸/透明底/来源 | 重写动画 |
| 运动不对 | 组件合同的 `motionPlan` / 曲线 / 阶段 | 换整段实现 |
| 节奏不对 | `from` / `durationInFrames` / `eventFrames` | 加转场糊过去 |
| 代码错 | 组件内部实现 | 改 scene spec 迁就代码 |
| 风格不对 | `VISUAL_DESIGN` / theme / 色板字体 | 逐镜手调颜色 |

> 先判断问题属于哪一层，再改那一层。跨层修改会让前后对照失效。

---

## 2. Studio 预览

```bash
cd ~/remotion/electron
npm run studio
```

- 做片时保持 Studio 打开，边做边看；
- 需要反复调的参数（亮度、幅度、角度、速度、透明度）暴露成 props，不写死在组件里；
- 能在 Studio 里调的，不要每次让 AI 改代码；
- Studio 里改的参数会写回代码：**改之前先存快照**。

---

## 3. 版本快照

每次改动前：

```bash
git add -A && git commit -m "snapshot: <场景> before <改动>"
# 或复制目录
cp -r components components.bak-$(date +%H%M)
```

- 快照必须包含：组件、scene spec、参数值；
- 不满意就回到快照，不许在坏版本上继续叠补丁；
- 对照实验保留两版，不覆盖。

---

## 4. 局部返工流程

1. **定位**：哪一场、哪一个组件、哪一帧开始不对；
2. **取证**：渲 3 帧（问题前 / 问题中 / 问题后）；
3. **改最小单位**：一个参数、一个路径、一个 `eventFrames`；
4. **重渲同帧**：和改前对比，确认问题真的解决；
5. **跑该场景验收帧**：不许只看改的那一帧；
6. **合并**：该场景通过后，再接入整片；
7. **记录**：改了什么、为什么、还留下什么。

---

## 5. 禁止的返工方式

- 因为一个参数不对，重写整段组件；
- 因为节奏不对，加转场/加光效掩盖；
- 因为运动不对，把 `path` 改成图片推拉；
- 因为资产不对，直接换一张照片了事；
- 不看渲染，只改文档；
- 改完不对比，直接说“好了”。

---

## 6. 迭代的出口

一个场景可以结束，当：

- 验收帧全部通过；
- 运动连续（看中间帧，不只看首尾）；
- 视觉审片通过（参考贴合、风格一致、层级清楚、节奏成立）；
- 改动已快照/提交；
- 没有未解释的降级。

> 迭代不是无限打磨。到“合同 + 验收 + 审片”都过，就停。
