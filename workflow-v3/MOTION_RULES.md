# 运动规则 · v3

> 目的不是“让画面动起来”，是让**该动的东西按叙事动**。
> 判断依据是渲染出来的帧，不是代码里用了多少 API。

---

## 1. 先识别机制，再选实现

每个场景先回答：**这一下是什么在变？**

| 机制 | 画面里发生什么 | 典型实现 |
|---|---|---|
| 路径 / 形变 | 轮廓改变、裂缝延伸、根系变长、笔画写出 | SVG `path`、`pathLength`、`strokeDashoffset`、路径插值 |
| 遮罩 / 揭示 | 信息被逐步揭开、遮挡关系改变、穿窗换景 | `clipPath`、`mask`、逐步显现 |
| 程序化 / 粒子 | 大量元素生成、生长、消散、错峰 | 确定性随机、循环 + 相位、Canvas |
| 分层 / 纵深 | 前后景相对运动、空间关系变化 | 多层位移、视差、景深模糊 |
| 文字构建 | 字逐字出现、重排、变形 | 逐字 `Sequence`、字距/基线插值 |
| 三维 | 真实空间、旋转、材质 | Three.js / R3F（未装则先别用） |
| 视频合成 | 实拍素材参与合成、被遮罩/跟踪/调色 | `<OffthreadVideo>` + 组件层 |
| 图像资产 | 高质量插画/背景作为主体，被分层、遮罩、局部运动组织 | 生成图 / 用户素材 + 组件层 |
| SVG 资产 | 线稿、图标、结构清晰的插画 | 路径数据 + 组件层 |
| 变换 | 位移、缩放、旋转、透明度 | `transform` / `opacity`（**允许，但不是默认**） |

> `transform` 本身没有问题。问题是**全片只有它**。
>
> 资产（图片/视频/SVG/3D）也可以是主体。判断标准不是“有没有素材”，
> 而是“素材有没有参与构图、运动、合成或叙事”。

---

## 2. 每个场景要有运动意图

不是“每镜至少 N 类运动”，而是这个场景内部发生了什么：

1. **入场**：主体怎么出现（落下 / 淡入 / 被揭示 / 从既有画面里长出来）；
2. **形成**：结构怎么建立（裂缝延伸 / 根系分叉 / 字形拼合）；
3. **聚焦**：注意力怎么转移（遮挡移除 / 对比出现 / 运动引导）；
4. **事件**：这一场景的核心变化（裂开 / 破土 / 开花 / 转变）；
5. **稳定**：结果怎么停留（保持 / 余震 / 光衰）。

- 五段可以不全有；但**事件**必须有，或明确写“本场景就是静止”。
- 静止不是失败：标题、阅读、情绪停顿都可以静止；但必须在 scene spec 的 `intent` 里写明。

---

## 3. 反例（直接判失败）

| 反例 | 为什么失败 |
|---|---|
| 全片 `translate + scale + opacity`，没有路径/遮罩/生成 | 这是图片轮播，不是动画设计 |
| 每镜一个推拉，镜与镜之间硬切 | 用运镜代替事件；节奏必然幻灯片 |
| 光效扫过、亮度变化被当成“事件” | 光在变，主体没变 |
| 用粒子/故障风掩盖没有结构 | 装饰不等于叙事 |
| 为了通过“死帧检查”给静止画面加抖动 | 指标优化，不是创作 |
| 组件内部只有 `<img style={{transform}}>` | 套了 React 外壳的幻灯片 |

---

## 4. 静止的判定

- 允许：scene spec 写明 `intent: "停顿/阅读/强调"`，并给出 `durationInFrames`；
- 不允许：没写理由的静止、连续两个场景都无事件、用静止逃避实现；
- 验收时**不按全局死帧阈值判失败**，按 scene spec 的预期判。

---

## 5. 运动质量的检查顺序

1. **结构**：这一场景的机制是什么？组件合同里写了吗？
2. **起止**：t0 和 t1 的状态是否与规格一致？
3. **中间**：中间帧是否连续、有没有跳变、有没有“直接跳到完成”？
4. **叙事**：遮住字幕，还能看出这件事发生了吗？
5. **节奏**：这个场景的长度和前后场景比，是否合理？

> 先看结构，再看帧；不要用“帧差很大”证明动画好。
