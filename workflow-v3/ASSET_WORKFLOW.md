# 资产工作流 · v3

> 资产不是原罪，**无设计的素材轮播**才是。
> 高质量插画、透明底 PNG、实拍视频、3D 模型都可以是画面的主体；
> 关键是它必须参与构图、运动、合成或叙事，而不是被推拉镜头拖着走。

---

## 1. 先选策略，再找资产

每个场景先回答：**这一场靠什么产生画面？**

| 策略 | 适合什么 | 不适合什么 |
|---|---|---|
| `procedural` | 路径生长、形变、粒子、数据变化、节奏同步 | 写实人物、复杂自然材质 |
| `svg-asset` | 线稿、图标、结构清晰的插画 | 路径太多、顺序混乱的复杂画面 |
| `generated-image` | 插画、背景、材质、风格化静帧 | 需要精确运动/逐帧控制的主体 |
| `video-footage` | 实拍氛围、真实运动、人物 | 需要精确对位、重复修改 |
| `3d-scene` | 真实空间、旋转、材质 | 本机未装 Three.js 时不要假装能做 |

> 选策略的依据是：**控制力、真实感、成本、可重复性**，不是“哪个听起来高级”。

---

## 2. 资产记录（每个资产一行）

| 字段 | 说明 |
|---|---|
| `path` | 文件路径；必须在工程内，不放 `/tmp` |
| `purpose` | 这一资产在画面里干什么（主体 / 背景 / 纹理 / 遮罩） |
| `size` | 像素尺寸；视频写时长/帧率 |
| `alpha` | 是否需要透明底 |
| `source` | 生成工具 / 用户提供 / 合法素材站；写清来源 |
| `license` | 授权信息；不确定就标“待确认” |
| `status` | 已取得 / 可生成（未生成）/ 需拍需找 / 没有 |
| `fallback` | 拿不到时怎么办；不许写“用照片顶上” |

**关键镜的资产必须是“已取得”**；`可生成` 只能进草稿，不能进正式制作。

---

## 3. 资产什么时候是主体

允许：

- 一张高质量插画，镜头围绕它做分层、遮罩、局部运动；
- 一段实拍视频，被合成进图形层、被跟踪、被调色；
- 一张透明底人物，参与构图和遮挡关系。

不允许：

- 每镜一张图 + 推拉/平移/裁切/淡入；
- 资产只是“背景板”，前面没有任何事件；
- 用资产数量代替运动设计；
- 资产来源不明、授权不清。

> 判断标准：**拿掉这张资产，这一镜的叙事是否还成立？**
> 成立 → 资产是装饰，要重新设计；不成立 → 资产是主体，必须写进 scene spec 的 `layers` 和 `motionPlan`。

---

## 4. 生成与获取

- 有图像生成工具时，允许生成插画/背景/材质；生成结果必须人工看一眼再用；
- 没有生成工具时，不许假装“已生成”；写“未接入”；
- 实拍素材：用户提供优先；素材站必须合法、记录来源；
- 3D：本机未装 Three.js/R3F 时，不许在合同里写 3D；
- 所有资产必须能离线复现；网络链接会失效。

---

## 5. 资产与场景规格的接口

```json
{
  "assetId": "seed-shell-texture",
  "path": "assets/seed-shell.png",
  "purpose": "种子外壳纹理，叠在 SVG 路径内",
  "size": "1024x1024",
  "alpha": true,
  "source": "generated-image",
  "license": "内部测试",
  "status": "已取得",
  "fallback": "无纹理纯色外壳，降低真实感"
}
```

- `assetId` 必须出现在使用它的组件 `props` 或 scene spec 的 `layers` 里；
- 资产不许在组件内部硬编码路径；
- 资产替换后，必须重跑验收帧。

- [ ] 每个场景的策略写了吗（procedural / svg / image / video / 3D）？
- [ ] 关键镜资产是“已取得”吗？
- [ ] 资产有来源、授权、尺寸、透明底说明吗？
- [ ] 拿掉资产，叙事还成立吗？成立就重新设计；
- [ ] 有没有“为了有素材而生成素材”？
- [ ] 资产替换后，验收帧重跑了吗？
